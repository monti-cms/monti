# 미디어 사용성 시험 09-3

- 환경: 기존 `http://localhost:4173`, Chromium 입력 드라이버, 1024×768. `e2e@example.dev`로 로그인. 모든 화면 조작은 `node testing/usability/do.ts`로 했다. 화면 경로는 이 저장소 기준이다.
- 화면 그림: `.usability/feat-media-09-3/` 아래. 키 입력 뒤에는 500ms 이상 기다려 촬영했다.

## 결함

### 1. A · 번역 이미지의 원문 따르기를 복원하면 영어 대체 텍스트가 사라진다

- 시나리오: U11.
- 입력 기록: 새 한국어 글 `미디어 사용성 시험`에 대표 이미지 `표지-봄.jpg`, 대체 텍스트 `봄 표지`를 넣어 발행 → `+ 언어` → `English` → 속성 열기 → 대체 텍스트에 `Spring cover` 입력 → 저장 → 게시글 목록으로 나가 글을 다시 열고 English와 속성 선택 → 대표 이미지에서 `서울의-밤.jpg` 올리기 → 대표 이미지 오른쪽 × 누르기.
- 화면: 입력 전 `.usability/feat-media-09-3/031-u11-en-properties.png`, 저장 후 재진입 `036-u11-reopen-fields.png`, 이미지 변경 `038-u11-override.png`, × 이후 `039-u11-follow.png`.
- 기대: 같은 원문 이미지를 쓰면서 영어 대체 텍스트를 유지하고, 번역 이미지를 변경한 후 다시 원문 이미지로 돌아갈 때 이미 쓴 영어 문구를 잃지 않고 작업을 마칠 수 있어야 한다. 09 문서 원칙 5는 대체 텍스트가 글에서 그림이 말하는 내용이라고 설명하고, 이 시험의 목표는 같은 파일과 영어 대체 텍스트를 함께 쓰는 것이다.
- 실제: `Spring cover`는 저장 후 재진입해도 남았으나, 이를 입력하는 순간 대표 이미지의 `원문의 발행본을 따라요`가 사라지고 ×가 생겼다. 이미지 변경 후 ×를 누르면 원문 이미지는 돌아오지만 영어 문구도 사라지고 `봄 표지`가 플레이스홀더로 나온다. 영어 문구를 유지하면서 이미지만 원문을 계속 따르게 하는 방법은 화면에서 찾지 못했다. 09 문서의 번역 미디어 필드 설명과 편집기 화면 규칙은 현재 대체 텍스트 입력도 필드 전체의 번역 값으로 만들고 ×가 전체 값을 지우도록 명시한다. 따라서 이 관찰은 구현의 문서 위반이라고 단정하지 않고, 요청된 사용 목적과 명시된 설계가 충돌하며 입력을 잃는 사용성 결함으로 기록한다.

### 2. B · 대체 텍스트만 바꾸어도 그림이 원문을 따르지 않는다는 변화가 드러나지 않는다

- 시나리오: U11.
- 입력 기록: 위와 같이 새 영어 번역의 속성을 열어 `원문의 발행본을 따라요`와 `표지-봄.jpg`를 확인 → 대체 텍스트에 `Spring cover` 입력 → 저장 후 재진입.
- 화면: `031-u11-en-properties.png`, `032-u11-en-save.png`, `036-u11-reopen-fields.png`.
- 기대: 그림의 출처와 동작을 사용자가 구분할 수 있어야 한다. 편집기 화면의 번역 대표 이미지 규칙은 원문 발행본을 따르는 동안 그 사실을 표시한다. 04 문서 원칙 5는 번역이 원문 발행본을 따른다고 설명한다.
- 실제: 원문 파일명과 썸네일은 그대로인데 설명 문구만 사라지고 ×가 생긴다. 그림을 따로 고른 적이 없으므로 이 그림이 이제 번역의 독립 값이라는 것을 화면에서 분명하게 알기 어렵다. 원문 변경 후 이 상태의 실제 전파 여부는 별도로 시험하지 않았다. ×를 눌렀을 때 영어 대체 텍스트가 사라지는 문제는 결함 1에 셌다.

## 관찰 기록

### U5 · 편집기

- `붙여넣기.png`를 붙이고 캡션 `그림 설명`을 썼다. 캡션에 포커스한 채 자르기와 회전 시트를 열어 오른쪽 회전, 자를 곳 잡기, 드래그, 적용 후 곧바로 `Meta+Z`를 눌렀다. 적용 직후와 되돌리기 직후에는 그림이 일시적으로 흐린 단색이었고, 이후 파란 원래 그림이 다시 보였다. 전후: `014-u5-before.png`, `017-u5-selected.png`, `018-u5-applied.png`, `019-u5-undo.png`, 이후 `025-u11-body-settings.png`. 적용된 잘린 결과가 완전히 로드된 화면을 되돌리기 전에 확인하지 못해 실제 자르기·회전의 시각적 전후 비교는 미완료다. 되돌리기 이후 원래 그림은 보였으나 두 변형이 각각 정상 적용되었는지는 판정하지 않는다.
- 캡션에서 시트를 열고 닫은 뒤 `focused`는 `본문` textbox를 가리켰다 (`020-u5-close.png`). 이는 편집기 화면의 시트 닫힘 포커스 규칙과 같다.
- 글머리와 번호 목록의 마지막 글 뒤에서 붙여넣고 바로 `이어쓰기`, `이어쓰기 번호`를 썼다. 각각 목록 뒤 이미지, 그 다음 문단에 글이 생겼다 (`054`~`058`).
- 번호 목록의 빈 첫 항목은 이미지가 앞에 놓이고 남은 `gamma`가 1번이었다 (`061`~`062`). 별도의 세 항목 목록에서 가운데 `beta`를 더블클릭해 지우고 붙이자 `alpha` 1번, 이미지, `gamma` 2번이었다 (`070`~`073`). 이어 빈 끝 항목에 붙이면 빈 항목은 사라지고 이미지가 들어갔다 (`074`~`075`). 하나뿐인 빈 항목에 붙였을 때 목록이 없어지고 이미지가 들어갔다 (`077`~`079`). 빈 항목 네 위치는 번호 목록에서만 확인했다.
- 번호 목록의 `gamma` 끝에서 `아주-큰-사진.png`를 붙이자 `image.png 19 MB · 10 MB까지`와 `줄여서 다시`가 보였다 (`063`, `064`). 이를 누른 뒤 그림이 표시되었고 (`065`), 저장 후 목록에서 글을 다시 열었을 때 그림과 `1. gamma`가 남았다 (`068`, `069`). 그림은 목록 바깥에 놓인다. 저장 후 목록과 그림의 전체 위치는 두 화면과 접근성 트리로 확인했다.
- 콘솔: 첫 확인 및 마지막 확인 모두 `[]`.

### U11 · 번역과 원문 발행

- 한국어 글을 발행하고 영어 번역을 만들어 대체 텍스트를 입력·저장·재진입했다. `Spring cover`는 남았다 (`036`). 영어 이미지를 `서울의-밤.jpg`로 바꿨고 (`038`), ×로 원문을 다시 따랐다 (`039`). 이때 영어 대체 텍스트 소실과 출처 표시 문제는 위 결함 참조.
- 한국어에서 대표 이미지를 `서울의-밤.jpg`로 바꾸고 저장만 한 후 (`048`), 영어 속성은 이전 `표지-봄.jpg`와 `원문의 발행본을 따라요`를 보였다 (`049`). 이 문구로 발행본을 따른다는 이유를 알 수 있다. 한국어를 다시 발행하자 영어 속성이 `서울의-밤.jpg`로 바뀌었다 (`051`, `052`). 이 발행 전후 시험은 ×를 눌러 영어 값을 비운 상태에서 했다. 대체 텍스트를 별도로 보존한 상태의 전파는 확인하지 못했다.
- 콘솔: `[]`.
