# 어시스턴트

이 페이지는 어시스턴트만 쓰는 부품을 다룬다. 대화, 도구 호출 줄, 시작할 요청, 입력 상자, 모델 선택기, 제안 카드의 틀이다.

패널 자체는 사이드 패널이다(오버레이 참고). 나머지는 다른 화면이 쓰는 부품 그대로다(2026-11-12 만들며 정함: 같은 일을 하는 것은 같은 부품으로 그린다). 무엇이 어느 자리에 오는지는 [화면 지도](../screens/assistant.md)에 있다.

| 어시스턴트 화면의 것 | 쓰는 부품 |
|---|---|
| 지난 대화 목록, 제안 카드의 줄, 검토 화면의 줄 | 공용 표(`Table`, `TableRow`, `RowTitle`, `RowMore`. [list.md](list.md)) |
| 검토 화면의 묶음 머리 | 제목 있는 목록(`ListSection table`. [list.md](list.md)) |
| 검토 화면의 바뀌는 글 | 번역 화면의 나란히 줄(`CompareRows`, `CompareRow`. [translation.md](translation.md)) |
| 줄 끝의 결과 | `EntryStatus`([status.md](status.md)) |
| 답하지 못한 것 | `ErrorNote`([status.md](status.md)) |
| 키가 없을 때, 지난 대화가 없을 때 | `Empty`([list.md](list.md)) |
| 입력란 위의 칩 | `Chip`([choice.md](choice.md)) |
| 며칠 뒤 지울지 | `Select`([field.md](field.md)) |
| 답 안의 간격, 도구 줄 묶음, 시작할 요청 묶음 | `Stack` |

2026-11-12에 없앤 부품: `ConversationList` · `ConversationGroupLabel` · `ConversationRow` · `ConversationRowMore`, `ReviewQuote` · `ReviewGroup` · `ReviewItem` · `ReviewCompareHead` · `ReviewCompare` · `ReviewLine` · `ReviewMore`, `ProposalRow` · `ProposalItem` · `ProposalEntry` · `ProposalActions` · `ProposalResult`, `ChatEntryList` · `ChatEntryLink`, `ChatDate`, `SuggestList` · `SuggestLabel`, `ChatAnswer` · `ToolCallLines`. 모두 위 표의 부품이 같은 일을 한다.

## 대화

대화는 패널 아래쪽, 입력 상자 위에 붙어서 위로 쌓인다. 요청 사이는 24px이다. 내 말은 오른쪽의 말풍선이다(종이). 함께 간 것이 있으면 말풍선 안 위에 mono 11로 붙는다("이 목록", "이 글 · 고른 글자"). 화면의 버튼(기본 요청)으로 보낸 말은 앞에 파란 반짝이가 붙는다. 어시스턴트의 답은 바탕 없이 그냥 글이다. 답 하나 안에서 도구 줄 묶음, 글, 카드, 오류 답장은 12px 간격으로 서고, 도구 줄끼리는 간격이 없다.

도구 호출은 mono 한 줄이다("✓ 글 목록 읽음 · 148편"). 하는 중이면 돌아가는 표시와 조금 진한 글("글 목록 읽는 중"), 실패했거나 끊겨 멈췄으면 빨간 ×와 빨간 글("글 · 여기서 멈춤")이다. 줄을 가리키면 꺾쇠가 보이고, 누르면 보낸 값이 열린다. 줄 하나는 24px이다: 줄이 붙어 서도 열리는 줄은 제 높이 전체가 눌린다.

아무것도 묻지 않은 패널은 설명 글이 없다. 대화 자리 아래쪽에 시작할 요청이 선다. 지금 화면의 기본 요청(반짝이)이 먼저, 전에 물은 것 둘(시계)이 그다음이다. 묶음 이름은 없다. 누르면 그 말로 바로 묻는다.

### 코드

`ChatThread`는 대화다. 24px 간격, 24px 안쪽 여백의 열이고 패널 아래에 붙어 위로 스크롤된다. 답 안의 간격은 화면이 `Stack`으로 준다. `ChatMessage`: `user`는 오른쪽의 종이 말풍선이고, `assistant`는 바탕 없는 그냥 글이다. `context`는 말풍선 안 위의 함께 간 것, `request`는 말 앞의 파란 반짝이다. 둘이 함께 있으면 반짝이는 함께 간 것의 줄 아래, 말과 같은 줄에 선다(만들며 정함 (2026-11-14). 따로 한 줄에 서던 것을 고쳤다). `streaming`은 답이 아직 오는 동안 마지막 단어 뒤에 깜박이는 얇은 커서를 보인다. 글이 아직 없으면 커서만 선다(보낸 순간부터 일하는 표시다). `ToolCallLine`: 호출 하나를 mono 한 줄로 보인다(24px). 어디까지 왔는지 표시(돌아가는 표시, ✓ 완료, 빨간 × 실패)하고, 한 일을 말로 적는다. `details`가 있으면 줄이 열려 보낸 값을 보이고(꺾쇠는 가리키거나 포커스가 있거나 열렸을 때만 보인다), 없으면 그냥 줄이다. `statusLabel`은 스크린 리더용 상태 설명이고 그려지지 않는다. `Suggest`는 시작할 요청 한 행이다(32px, `height-control-md`). `request`는 반짝이가 붙은 기본 요청, `recent`는 시계가 붙은 전에 했던 요청이다.

`ChatMessageActions`: 메시지 하나 바로 아래의 줄이다. 보낸 시각(caption, `fg-faint`)과 아이콘만 있는 작은 `IconButton`(24px, 아이콘 14px, 부가 정보라 `fg-faint`이고 가리키면 진해진다)들을 담고(줄이 `IconButtonContext`로 `size="xs"`, `tone="quiet"`를 알려 준다. 부르는 쪽은 그냥 `IconButton`을 넣는다), 메시지와 같은 쪽에 붙는다(`user`는 오른쪽, `assistant`는 왼쪽). 포인터나 키보드가 그 메시지나 이 줄에 있을 때만 보이고 터치 화면에서는 늘 보인다(가리킬 포인터가 없다). 이 줄은 대화의 간격을 더하지 않고 그 안에 든다: 24px 간격의 열에서 말 4px 아래, 다음 것 8px 위에 서서, 말에서 다음 것까지는 줄이 보이든 아니든 36px다(줄이 없는 두 것 사이는 대화의 24px 그대로). 나타나도 아무것도 움직이지 않는다. 전에는 줄이 간격에 더해져 56px였고 대부분이 빈 자리였다(2026-11-12 소유자: "그래도 좀 넓긴함". 36이라는 수는 2026-11-13 만들며 정함. 레퍼런스로 Claude, ChatGPT, Cursor를 떠올려 견줬고 직접 재지는 못했다: 셋 다 말 아래 버튼 줄을 말에 바짝 붙이고 다음 말까지의 자리를 따로 크게 비우지 않는다). 버튼 이름은 툴팁과 스크린 리더 이름으로만 있고 글자로 그리지 않는다. 관리자 메시지는 시각 · 복사(`Copy`) · 고쳐서 다시 보내기(연필), 어시스턴트 답은 복사 · 다시 하기(`Renew`)다. 고쳐서 다시 보내기와 다시 하기는 마지막 말에만 있다.

## 제안 카드

대화 안의 제안 카드다(흐름 2·11, 16). 틀만 이 부품이다. 머리는 "제안 · 2묶음 · 3건"이고 상태는 싣지 않는다. 그 아래 바뀌는 것이 공용 표의 줄로 온다(검토 화면의 줄에서 체크만 뺀 줄). 맨 아래 발 한 줄이 상태를 말하고 전부에 대해 할 수 있는 일을 담는다: 기다리는 동안 "검토" · "버리기" · [3건 적용], 적용하는 동안 "적용 중 2 / 3"과 진행 막대, 적용한 뒤 "✓ 2건 적용" · "1건 못 함" · "되돌리기", 그 뒤에는 "되돌림"이나 "버림". 버린 제안은 카드가 흐려진다. 같은 한 줄이 검토 화면 머리 끝에도 선다.

### 코드

`ProposalCard`: `title`, `summary`(mono 11의 양), `muted`(버림), 맨 아래 `footer`. 줄은 `Table`이고 발은 화면이 채운다.

## 입력 상자

어시스턴트 입력 상자다. 왼쪽 아래에 모델 선택기가 있고(대화마다 기억한다), 오른쪽에 둥근 보내기 버튼이 있다. 답을 쓰는 동안 보내기 버튼은 멈춤이 된다. 함께 가는 것은 글 위의 칩이다("이 글 ×", "고른 글 2편 ×"). ×로 빼면 그것은 가지 않고, 다른 글을 열거나 다른 행을 고르면 칩이 다시 생긴다. 글이 비어 있으면 보내기 버튼만 흐려진다.

### 코드

`ChatInput`: 글 영역이 든 둥근 상자다(모서리 24px. 안의 모델 알약과 보내기 버튼이 가장자리에서 8px 떨어져 곡률이 함께 간다). 그 아래 행의 앞쪽에 `aside`(모델 선택기)가, 끝에 둥근 보내기 버튼이 있다. 이 버튼은 답을 쓰는 동안 멈춤 버튼이 된다(`busy`). `context`는 글 위의 칩 자리다. Enter는 보내고 Shift+Enter는 줄을 바꾼다(입력기가 글자를 조합하는 중에는 아니다). 글이 비어 있거나 상자가 `disabled`이면 아무것도 보내지 않는다. `disabled`는 지금 정말 보낼 수 없을 때만 쓰고(모델이 없음), 그 까닭은 상자 바로 옆, 사람이 쓰려는 그 자리에서 읽힌다(원칙 7). 흐린 상자만 두고 끝내지 않는다. 문구는 앱이 정한다. `queue`는 어시스턴트가 일하는 동안 보낸 말이 기다리는 줄이다. 상자 위에 상자와 같은 폭의 카드(`bg-selected`)로 그려지고, 카드 아래쪽은 상자 뒤로 24px 숨는다(상자 모서리의 곡률만큼: 카드의 곧은 변이 상자의 둥근 윗변 뒤를 지난다). `busy`이고 `onQueue`가 있으면 Enter와 보내기는 막히지 않고 글을 이 줄에 넣는다. 멈춤 버튼은 그대로 있다. `busyPlaceholder`는 그동안의 안내 글이다("더 말하기"). 글자를 조합하는 중의 Enter(한글 한 글자를 끝내는 Enter. Safari는 조합이 끝난 뒤에 키 코드 229로 보낸다)는 보내지 않는다. 기다리는 메시지의 카드(`queue`)가 생기고 사라져도 입력란은 같은 요소로 남는다: 치던 글과 커서, 포커스가 그대로다. 멈춤 버튼에 키보드 포커스가 있을 때 답이 끝나 보내기 버튼으로 바뀌면 포커스는 글 영역으로 간다(빈 상자의 보내기는 꺼져 있어 포커스를 받지 못한다).

`ChatQueueItem`: 어시스턴트가 일하는 동안 관리자가 보낸 말 하나다. `ChatInput`의 `queue`에서 기다리다가 어시스턴트가 받아들이면 줄에서 빠지고 대화에 메시지로 나타난다. 말은 잉크 한 줄(넘치면 줄임)이다. 글은 13px(`note`)이고, 뒤에 작은 아이콘 버튼(`IconButton size="xs" tone="quiet"`, 24px, 아이콘 14px, `fg-faint`, 가리키면 진해진다) 셋이 늘 보인다. 20px 버튼은 없다. 줄 사이는 4px다. 지금 보내기(↑), 고치기(밑줄 없는 연필 `Pen`. 말이 상자로 돌아가고 포커스가 간다. 호출하는 쪽이 `onEdit`에서 한다), 취소(휴지통). 이름은 툴팁뿐이다. 개수 표시나 "모두 지금 보내기"는 없다.

## 모델 선택기

입력 상자 왼쪽 아래의 `모델 · 생각 정도 ▾`다. 누르면 위로 메뉴가 열린다(`.mt-card` + 메뉴 부품).

- 맨 위에 검색 행이 있다(`.mt-menu-search`). OpenRouter 같은 키는 모델이 수백 개라서 찾기가 먼저다.
- 목록은 회사가 아니라 키로 묶는다. 맨 위에 최근에 쓴 모델을 모은 "최근" 그룹이 있고, 그룹 이름 옆에 개수가 있다. 목록은 안에서 스크롤된다(`.mt-menu-scroll`).
- 모델 이름은 mono 12다(`.mt-menu-item.is-mono`). 기본 모델에는 "기본" 표시가 붙는다. 도구를 쓸 수 없는 모델은 목록에 없다.
- 마지막 행은 "생각 › 보통"이다. 둘째 단계에서 "끔" · "낮음" · "보통" · "높음" 중 하나를 고른다. 모델이 생각을 지원하지 않으면 이 행은 빠진다.
- 고른 모델과 생각 정도는 대화마다 기억한다. 새 대화는 내장 기본 모델(키가 있는 첫 서비스의 기본 모델)에서, 생각할 수 있는 모델이면 "보통"에서 시작한다. 대화의 키가 지워졌으면 사이트에 남은 키의 기본 모델로 간다.
- 같은 메뉴가 API 키 화면의 "모델 › 빠른 작업" 칸에서도 열린다. 거기서는 칸 아래로 열리고 칸의 너비를 따르며, "최근"과 생각 행이 없다. 고르면 바로 적용하고 토스트를 띄운다.

### 코드

`ModelMenu`: 검색 행, 묶음(`groups`: 이름, 개수, 모델 행), 지금 모델의 ✓, 생각할 수 있는 모델의 "생각 ›" 행(`thinking`, 넘기지 않으면 행이 없다)이 든 메뉴다. 검색은 모델 이름으로 거른다. `layout="chat"`은 입력 상자 위로 330px 너비로 열리고(목록 최대 352px), `layout="field"`는 칸 아래로 칸 너비로 열린다(목록 최대 236px). 모델 행은 mono 12이고, 끝의 짧은 말(`hint`: "기본", 최근 모델의 키 이름)은 mono 11이다. `ModelMenuButton`은 입력 상자의 모델 버튼이다: mono 모델 이름, 생각하는 모델이면 흐린 "· 생각 높음", 그리고 `Caret`. `Button variant="ghost" size="sm"`이다([common.md](../screens/common.md)의 메뉴 표와 같다). 쉴 때는 바탕이 없고, 메뉴가 열리면 ghost 바탕에 잉크다. 칸으로 여는 쪽은 `MenuField`(필드 페이지)다.

## 막혔을 때

보내기는 막지 않는다. 보낸 뒤에 할 수 없는 일이 생기면 대화 안의 오류 답장으로 알린다(`ErrorNote`, [status.md](status.md)). 왼쪽에 빨간 선 하나, 굵은 빨간 제목 한 줄, 회색 한 줄, 그 아래 할 수 있는 일이 온다. 제목은 짧고 짐작한 까닭이나 고치는 법을 적지 않는다: "서비스가 거절했습니다"(회색 줄에 키 이름과 서비스가 한 말 그대로), "서비스가 답하지 않습니다", "연결이 끊겼습니다", "한도에 닿아 멈췄습니다". Monti는 돈을 세지 않으므로 금액이나 한도를 보이지 않는다. 말과 할 수 있는 일의 표는 [화면 지도](../screens/assistant.md)에 있다.
