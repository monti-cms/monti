# 흐름 10: API 키

이 파일은 캔버스 흐름 10 "흐름 10 · API 키"의 모든 행과 단계를 적는다. 키 추가, 확인, 편집, 지우기, 플러그인 키, 빠른 작업 모델, 예외를 다룬다.

캔버스 메모: "흐름 10 · API 키 — 추가 · 확인 · 편집 · 지우기 · 플러그인 키 · 빠른 작업 모델 · 예외"

쓰는 화면: [`ApiKeys`](../screens.md#apikeys).

보드는 흐름의 순서만 보인다. 단계의 글은 화면 승인(2026-11-12, [기능 설계 14](../../features/14-data-keys-plugins.md))에서 정한 대로 적었고, 보드와 다르면 이 글이 맞다.

단계는 흐름 테스트의 계약이다. 단계마다 보드 파일, 그리는 화면과 상태, 사용자가 하는 일과 보는 것을 적는다. 번호에 글자가 붙은 단계(예: 04b)는 바로 앞 단계의 변형이거나 그다음 순간이다.

## "키 추가"

### 단계 01: "키 추가 · + 키 추가 → 서비스 고르기"

- 보드: `Flow10Step01.dc.html`
- 화면: `ApiKeys` (stage "서비스 고르기")
- 사용자가 도구 › API 키에서 "+ 키 추가"를 누른다. 서비스 고르기가 열린다. 서비스는 Anthropic, OpenAI, OpenRouter, Google, OpenAI 호환 주소다. Ollama는 줄이 따로 없고 "OpenAI 호환 주소"에 그 주소를 넣어 쓴다. 묶음 이름("AI", "플러그인")은 플러그인이 자기 서비스를 더했을 때만 보인다.

### 단계 02: "키 추가 · 서비스를 고른 뒤 · 이름은 서비스 이름으로 채워져 있음 · 키"

- 보드: `Flow10Step02.dc.html`
- 화면: `ApiKeys` (stage "키 입력")
- 서비스를 고르면 같은 창이 추가 대화상자가 된다. 이름은 서비스 이름으로 이미 채워져 있고, 키 칸(자리 표시 글자 sk-ant-…)과 추가 버튼이 있다.

### 단계 02b: "키 추가 · OpenAI 호환 주소 → 주소 칸이 더해짐 · 이름은 주소의 호스트로 채워짐"

- 보드: `Flow10Step02b.dc.html`
- 화면: `ApiKeys` (stage "호환 주소")
- OpenAI 호환 주소를 고르면 주소 칸이 더해진다. 이름은 그 주소의 호스트로 채워진다.

### 단계 03: "키 추가 · 추가 → 서비스에 확인하는 중…"

- 보드: `Flow10Step03.dc.html`
- 화면: `ApiKeys` (stage "확인하는 중")
- 사용자가 추가를 누른다. 대화상자에 "확인하는 중…"이 나온다.

### 단계 04: "키 추가 · 서비스가 받아 주지 않음 → 키 칸 아래 한 줄 · 창은 열린 채"

- 보드: `Flow10Step04.dc.html`
- 화면: `ApiKeys` (stage "키 거절")
- 서비스가 키를 받아 주지 않는다. 키 칸 아래 한 줄이 키가 맞지 않는다고 알린다("맞지 않는 키입니다."). 대화상자는 열린 채로 남는다. 서비스에 닿지 못했으면 같은 자리에 "서비스가 답하지 않습니다."(호환 주소는 주소 칸 아래)이고, 다시 누르면 다시 묻는다.

### 단계 05: "키 추가 · 같은 이름의 키가 이미 있음 → 이름이 "Anthropic 2"로 채워짐 · 한 줄"

- 보드: `Flow10Step05.dc.html`
- 화면: `ApiKeys` (stage "이름 겹침")
- 같은 이름의 키가 이미 있다. 이름이 "Anthropic 2"로 채워지고, 그 이름의 키가 있다는 한 줄이 나온다.

### 단계 06: "키 추가 · 추가됨 → 목록에 새 줄 · 토스트"

- 보드: `Flow10Step06.dc.html`
- 화면: `ApiKeys` (stage "추가됨")
- 키가 추가됐다. 목록에 새 행(이름, 마지막 네 글자)이 생기고, 토스트가 "키를 추가했습니다"라고 알린다.

## "편집"

### 단계 07: "편집 · 편집 → 서비스는 글자로 · 이름 · 키는 ··· a1b2 · 바꾸기"

- 보드: `Flow10Step07.dc.html`
- 화면: `ApiKeys` (stage "편집")
- 사용자가 키 줄 끝의 ⋯에서 "편집"을 누른다. 서비스는 그냥 글자로 보이고, 이름은 고칠 수 있으며, 키는 "··· a1b2"와 "바꾸기" 동작으로 보이고, 저장 버튼이 있다.

### 단계 08: "편집 · 바꾸기 → 빈 키 칸이 열림 · 그대로를 누르면 ··· a1b2로 돌아감"

- 보드: `Flow10Step08.dc.html`
- 화면: `ApiKeys` (stage "편집 키 열기")
- 사용자가 바꾸기를 누른다. 빈 키 칸이 열린다. "그대로"를 누르면 "··· a1b2"로 돌아간다.

### 단계 09: "편집 · 새 키 → 저장 → 확인하는 중… (03 · 04와 같은 확인, 같은 이름은 05와 같은 한 줄)"

- 보드: `Flow10Step09.dc.html`
- 화면: `ApiKeys` (stage "편집 확인 중")
- 사용자가 새 키를 넣고 저장한다. 대화상자에 "확인하는 중…"이 나온다. 확인은 단계 03, 04와 같고, 이름이 겹치면 단계 05와 같은 줄이 나온다.

### 단계 10: "편집 · 저장됨 → 줄에 새 끝자리 · 토스트"

- 보드: `Flow10Step10.dc.html`
- 화면: `ApiKeys` (stage "편집 저장됨")
- 저장됐다. 행에 새 마지막 네 글자가 보이고, 토스트가 "저장했습니다"라고 알린다.

## "지우기"

### 단계 11: "지우기 · 줄의 지우기 → 쓰는 곳이 있으면 확인에 멈추는 곳 목록 · 빨간 지우기"

- 보드: `Flow10Step11.dc.html`
- 화면: `ApiKeys` (stage "지우기 확인")
- 사용자가 키 줄 끝의 ⋯에서 "지우기"를 누른다. 확인 창의 질문은 "키를 지울까요?"이고 이름을 넣지 않는다. 되돌릴 수 없고 이 키를 쓰는 곳이 멈춘다고 알린다. 그 아래 첫 줄이 그 키의 이름이고, 이어서 멈추는 곳을 모델 이름과 함께 나열한다(어시스턴트 claude-sonnet-5-5, 빠른 작업 claude-haiku-5-5). 지우기 버튼은 빨갛다. 지우면 줄이 사라지고 토스트가 "키를 지웠습니다"라고 알린다.

### 단계 11b: "지우기 · 쓰는 곳이 없어도 확인 (되돌릴 수 없음)"

- 보드: `Flow10Step11b.dc.html`
- 화면: `ApiKeys` (stage "쓰는 곳 없이 지우기")
- 아무 데서도 쓰지 않는 키도 확인을 거친다("되돌릴 수 없습니다."). 창에는 그 키의 이름 한 줄만 있다.

## "플러그인 키"

### 단계 12: "플러그인 · 키 넣기 → 서비스가 정해진 키 창"

- 보드: `Flow10Step12.dc.html`
- 화면: `ApiKeys` (stage "키 넣기")
- 플러그인 키다. 플러그인 키 행(맞춤법 검사, 검색 키)이 비었으면 줄 끝에 "키 넣기"가 있다. 누르면 AI 키와 같은 키 창이 서비스가 정해진 채로 열린다(서비스는 글). 키를 넣고 "추가"하면 서비스에 한 번 확인한다. 받아 주지 않으면 창이 열린 채 키 칸 아래 한 줄(2026-11-05 소유자: 키 줄은 모두 같은 방법이다). 창에는 "서비스"와 "키"만 있고 "이름" 칸은 없다: 줄의 이름은 플러그인의 이름이다(만들며 정함 2026-11-13, 기능 설계 14).

### 단계 12b: "키 넣음 → 줄에 끝 네 자리 · ⋯ · 토스트"

- 보드: `Flow10Step12b.dc.html`
- 화면: `ApiKeys` (stage "키 넣음")
- 키가 들어갔다. 플러그인 행 이름 뒤에 끝 네 자리 "··· 4410"이 보이고, 줄 끝의 "키 넣기"가 ⋯("편집" · "지우기")로 바뀐다(AI 키 줄과 같다). 토스트가 "바른 맞춤법에 키를 넣었습니다"라고 알린다. "AI 키" 표에는 행이 생기지 않는다.

## "빠른 작업 모델"

### 단계 13: "빠른 작업 모델 · 모델 메뉴 (흐름 2의 고르기, 키마다 묶음)"

- 보드: `Flow10Step13.dc.html`
- 화면: `ApiKeys` (stage "모델 고르기")
- 빠른 작업 모델이다. 사용자가 빠른 작업(✦ 채우기, 고른 글자의 "요청", "✦ 번역")에 쓸 모델 메뉴를 연다. 흐름 2와 같은 고르기로, 검색창이 있고 모델은 키마다 묶여 있다.

### 단계 13b: "빠른 작업 모델 · 고르면 바로 바뀜 · 토스트"

- 보드: `Flow10Step13b.dc.html`
- 화면: `ApiKeys` (stage "모델 바뀜")
- 모델을 고르면 바로 바뀐다. 토스트가 "빠른 작업 모델을 바꿨습니다"라고 알리고, 행에 그 모델이 보인다.

## "예외"

### 단계 14: "예외 · 읽을 수 없는 키 (서버 비밀값이 바뀜) → 줄마다 표시"

- 보드: `Flow10Step14.dc.html`
- 화면: `ApiKeys` (stage "읽을 수 없음")
- 예외: 서버 비밀값이 바뀌어 키를 읽을 수 없다. 화면 맨 위(제목과 탭보다 위, 틀의 띠 자리)의 알림 띠가 "키 3개를 읽을 수 없습니다"라고 알리고 뒤에 `MONTI_SECRET 변경`이 붙는다. 키 행마다 둘째 줄이 빨간 "읽을 수 없음"이고, "편집"은 다른 줄처럼 줄 끝 ⋯에 있다.

### 단계 14b: "예외 · 읽을 수 없는 키 · 편집 → 키 칸에 초점 · 키를 다시 넣어 주세요 (키 필수)"

- 보드: `Flow10Step14b.dc.html`
- 화면: `ApiKeys` (stage "다시 넣기")
- 사용자가 읽을 수 없는 키의 ⋯에서 "편집"을 누른다. 키 칸에 포커스가 가고, 키를 다시 넣으라는 말이 나온다. 저장하려면 키가 있어야 한다.

### 단계 15: "예외 · MONTI_SECRET 없음 → 배너 하나 · 키 추가와 키 자리가 숨음"

- 보드: `Flow10Step15.dc.html`
- 화면: `ApiKeys` (stage "비밀값 없음")
- 예외: MONTI_SECRET이 설정되지 않았다. 화면 맨 위의 알림 띠 하나가 "키를 저장할 수 없습니다"라고 알리고 뒤에 `MONTI_SECRET 없음`이 붙는다. 어떻게 고치는지는 적지 않는다. 할 수 없는 것은 흐리게 두지 않고 숨긴다. "+ 키 추가", "모델" 묶음, "플러그인 키"의 빈 자리가 없다(키가 든 자리는 AI 키처럼 남아 "지우기"만 있다. 만들며 정함 2026-11-13). 키가 하나도 없으면 띠만 있고, 전에 넣은 키가 있으면 "읽을 수 없음"으로 보이며 ⋯에는 "지우기"만 있다.
