# 16 사이트에 붙이기

상태: 범위만 (2026-11-11). 설계 전이다. 진행 기록에서 "출시 전"으로 미뤄 둔 일을 모아 문서로 세웠다.

## 한 문장

사이트 코드가 Monti를 꽂는 길이다. 관리자 화면과 관리자 API를 사이트의 라우트에 올리고, 발행본을 읽어 그리고, 미리보기와 캐시 갱신을 받는다. 예제 앱 하나가 이 길로 설치부터 발행까지 돈다.

## 범위

[진행 기록](../../tracker.md)의 남은 일이다. 설계할 때 이 표를 기능 목록과 끝 조건으로 바꾼다.

| 번호 | 무엇 |
|---|---|
| T13 | Next 어댑터(관리자 경로, 관리자 API, 미리보기), 사이트에서 글 읽기(`createReader`), 예제 앱. 개발 서버가 시작할 때 `syncSchemaFile`, 운영 사이트의 `db:migrate` 누락 알림 |
| T82 | `monti init`(설정 마법사, 로그인 고르기)과 `monti doctor`(설정 점검) |
| T83 | 개발 서버에서 로그인 건너뛰기 |
| T102 | S3 호환 저장소 어댑터와 브라우저가 저장소로 직접 올리는 길 |
| T81 | 사이트 그리기의 목차와 제목 앵커(`tocOf`) |
| T14 | 릴리스 묶음. `@monti-cms/admin`에는 아직 빌드와 내보낼 파일 목록이 없다. 예제 앱이 묶음에서 설치해 도는 것으로 확인한다 |

## 설계에서 정할 것

- 어댑터가 사이트에 내놓는 것: 관리자 페이지, 관리자 API 라우트, 미리보기 라우트, 캐시 갱신을 받는 곳.
- 12번의 값(미리보기 경로, 경로의 언어, 주소에 언어 표시)을 사이트가 어떻게 읽고 따르는가.
- 13번 이벤트의 `paths`로 사이트 캐시를 갱신하는 길.
- 관리자 주소는 사이트의 라우트 폴더가 정한다. 설정 화면이 그 값을 보일지.
- 개발 서버인지 아는 법(12번)을 어댑터가 어떻게 넘기는가.
- 예제 앱이 시험용 서버(`testing/e2e`)를 대신하는가.
