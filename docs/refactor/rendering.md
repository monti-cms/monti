# 본문 렌더링 이관 기록

상태: core에서 제외, 외부 소유 위치는 미확정 (2026-11-18).

## 1. 받는 일

- 기존 `render.ts`의 `renderDocument`: 문서 JSON을 문단·제목·목록·표·각주·이미지·파일 등 화면 요소로 만드는 기능.
- `CreateElement`, `RenderOptions`, `BlockProps`, `MarkProps`와 블록·서식의 `Site` 컴포넌트 계약. core의 문서 데이터 타입을 사용하며 화면 계약을 core로 역수입하지 않는다. 블록을 그리는 컴포넌트는 CMS의 블록 정의에 담지 않으므로([blocks.md](blocks.md)), 사이트가 이를 렌더러에 어떻게 연결할지는 이 문서의 작업에서 정한다.
- 제목 ID·목차의 표시 계약, 글 링크의 표시, 본문 렌더링 CSS, 이미지 프레임·사이트 이미지 표시 도구.
- 코드 블록의 화면 표현은 [blocks.md](blocks.md)의 도구를 사용한다. 실제 파일 URL·참조·문서 데이터는 core의 공개 조회 결과로 받으며 렌더러가 DB를 읽지 않는다.
- 기존 `@monti-cms/core/render`, `@monti-cms/core/render.css` 소비자를 외부 경로로 바꾼다. admin의 읽기 전용 본문, 사이트, 블록의 화면 컴포넌트와 테스트 연결을 함께 확인한다.

## 2. 남겨 두는 책임

- 문서·블록의 데이터 구조·검증은 core의 `rich-text/`에 남는다.
- 저장된 미디어 데이터의 무결성과 참조 색인은 core 리소스의 책임이다. 이미지 배치·색·HTML 요소 선택 같은 표시 정책은 이쪽의 책임이다.
- 발행본·작업본 선택 규칙은 core Operation이 담당한다. 렌더러에 별도 `Reader`나 사이트용 데이터 접근 규칙을 만들지 않는다.

## 3. 이 기능의 테스트 계획 전에 정할 것

- 렌더러를 기존 블록·사이트 연결 패키지에 둘지, 독립 패키지가 필요한지. 새 패키지 이름은 아직 정하지 않는다.
- 프레임워크와 무관한 요소 생성 계약을 유지할지, 각 연결 패키지의 화면 계약으로 나눌지.
- 사이트와 admin이 공유할 표시 범위, CSS·브라우저 상호작용 코드의 실제 소유 위치.

분리 결정을 이유로 사이트의 기존 표시 기능을 조용히 없애지 않는다. 유지·변경·폐기할 동작은 이 기능의 상세 설계에서 소유자와 정한다.
