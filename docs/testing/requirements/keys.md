# 요구사항: AI의 API 키 저장

상태: 초안 (2026-10-31).

중요도: [기능의 중요도](../features.md)의 ai "API 키 저장". 흐름 10(API 키)의 화면이 쓰는 저장 방식이다. 어시스턴트의 다른 동작은
에이전트로 다시 짤 때 표를 만든다([계획](../plan.md)). 읽는 법은 [휴지통](trash.md#읽는-법)과 같다.

## 비밀값 🔴

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| KEY-S1 | 비밀값은 플러그인마다 다른 키로 암호화해 저장하고 원문을 남기지 않는다. 다른 플러그인, 다른 비밀, 키 id를 고친 값으로는 읽지 못하고, 깨진 값은 오류 대신 읽지 못함이 된다 | 데이터베이스가 새면 AI 서비스의 키도 샌다 | 코드 | L1 |
| KEY-S2 | `MONTI_SECRET`을 바꿔도 이전 비밀(`previousSecrets`)로 저장한 값을 읽고, 그 값이 지금 비밀의 것이 아님을 알린다 | 비밀을 바꾸면 저장한 키를 모두 다시 넣어야 한다 | 코드 | L1 |
| KEY-S3 | 인스턴스와 서버 설정에는 원문 비밀이 없고, 비밀 없이 암호화하라고 하면 거부한다 | 비밀이 로그나 화면에 나온다 | 코드 | L1 |

## 키 저장소 🔴

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| KEY-A1 | 입력한 키는 키 저장소에 넣고 연결에는 그 id만 둔다. 화면은 끝 네 글자만 받는다 | 화면을 보는 사람이 키 전체를 본다 | 흐름 10 | L1 |
| KEY-A2 | 연결을 저장하지 못하면 방금 저장한 키를 지운다. 연결을 지워도 키는 남고, 키 값을 바꾸면 그 키를 쓰는 모든 연결이 따라간다. 키를 보내지 않으면 저장된 키를 쓰되, 주소가 다른 연결로는 옮기지 않는다 | 키가 다른 서비스의 주소로 보내진다 | 흐름 10 | L1 |
| KEY-A3 | 인스턴스에 비밀이 없으면 키 저장을 거부하고 고치는 법을 알린다 | 키가 암호화되지 않은 채 저장된다 | 코드 | L1 |
