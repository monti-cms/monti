# 요구사항: API 키

상태: 초안 (2026-10-31).

흐름: [흐름 10 · API 키](../../design/admin/flows/10-api-keys.md). 중요도: [기능의 중요도](../features.md)의 ai "API 키 저장" 🔴과 "10 API 키" 🟡.
흐름 10의 화면이 쓰는 저장 방식과 그 화면이다. 어시스턴트의 다른 동작은 에이전트로 다시 짤 때 표를 만든다([계획](../plan.md)). 읽는 법은
[휴지통](trash.md#읽는-법)과 같다.

## 비밀값 🔴

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| KEY-S1 | 비밀값은 플러그인마다 다른 키로 암호화해 저장하고 원문을 남기지 않는다. 다른 플러그인, 다른 비밀, 키 id를 고친 값으로는 읽지 못하고, 깨진 값은 오류 대신 읽지 못함이 된다 | 데이터베이스가 새면 AI 서비스의 키도 샌다 | 코드 · 소유자 확인 (2026-10-31) | L1 |
| KEY-S2 | `MONTI_SECRET`을 바꿔도 이전 비밀(`previousSecrets`)로 저장한 값을 읽고, 그 값이 지금 비밀의 것이 아님을 알린다 | 비밀을 바꾸면 저장한 키를 모두 다시 넣어야 한다 | 코드 · 소유자 확인 (2026-10-31) | L1 |
| KEY-S3 | 인스턴스와 서버 설정에는 원문 비밀이 없고, 비밀 없이 암호화하라고 하면 거부한다 | 비밀이 로그나 화면에 나온다 | 코드 · 소유자 확인 (2026-10-31) | L1 |

## 키 저장소 🔴

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| KEY-A1 | 입력한 키는 키 저장소에 넣고 연결에는 그 id만 둔다. 화면은 끝 네 글자만 받는다 | 화면을 보는 사람이 키 전체를 본다 | 흐름 10 | L1 |
| KEY-A2 | 연결을 저장하지 못하면 방금 저장한 키를 지운다. 연결을 지워도 키는 남고, 키 값을 바꾸면 그 키를 쓰는 모든 연결이 따라간다. 키를 보내지 않으면 저장된 키를 쓰되, 주소가 다른 연결로는 옮기지 않는다 | 키가 다른 서비스의 주소로 보내진다 | 흐름 10 | L1 |
| KEY-A3 | 인스턴스에 비밀이 없으면 키 저장을 거부하고 고치는 법을 알린다 | 키가 암호화되지 않은 채 저장된다 | 코드 · 소유자 확인 (2026-10-31) | L1 |
| KEY-A4 | 쓰는 곳이 있는 키는 `force` 없이는 지우지 않고, 멈출 곳의 목록과 함께 `key_in_use`로 답한다. 플러그인의 키 칸에 넣은 키도 쓰는 곳이다. 쓰는 곳의 목록은 읽을 때 플러그인이 주는 이름으로 만들고 사라진 항목은 뺀다. 키를 지우면 그 키를 쓰던 기록도 함께 지운다. KEY-W2(화면이 늘 묻는다)의 서버 쪽이다 | 어시스턴트가 쓰는 키가 확인 없이 지워지거나, 지우기 확인이 멈출 곳을 빠뜨린다 | 흐름 10·11 · 소유자 확인 (2026-10-31) | L1 |

## 화면 🟡

화면이 끝 네 글자만 보이는 것은 KEY-A1, 비밀값 없이 키 추가를 막는 것은 KEY-A3이다. 테스트가 없는 보드의 단계(서비스가 키를 받지 않음 10·4,
편집과 바꾸기 10·7~10, 읽을 수 없는 키 10·14)는 🟡라 줄을 더하지 않았다. 같은 이름(10·5)은 core에 테스트가 있어 KEY-N1이 되었다.

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| KEY-W1 | "+ 키 추가"로 서비스를 고르고 이름과 키를 넣으면 키가 추가되고, 목록에 이름과 끝 네 글자의 새 줄이 생긴다 | 넣은 키가 저장되지 않는다 | 흐름 10·1~6 | L3 |
| KEY-W2 | 키를 지울 때는 늘 묻는다. 쓰는 곳이 있으면 멈추는 곳을 나열하고, 확인해야 그 연결까지 지운다 | 쓰는 곳을 모르고 지워 어시스턴트가 멈춘다 | 흐름 10·11, 10·11b | L3 |
| KEY-W3 | 플러그인의 키 칸은 키가 없으면 "키 없음" 줄로 보이고 필요한 수로 센다. 저장된 키나 새 키(같은 요청으로)를 넣고, 키 줄의 메뉴에서 뺀다 | 맞춤법 검사에 키가 필요한 것을 모른다 | 흐름 10·12, 10·12b | L3 |

## 키 이름과 플러그인의 키 칸 🟡

[기능의 중요도](../features.md)의 "API 키의 이름, 플러그인의 키 칸 API" 🟡(제안대로, 2026-10-31). 화면의 키 칸은 KEY-W3이다.

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| KEY-N1 | 키 이름은 대소문자를 가리지 않고 하나뿐이다. 겹치면 `key_name_taken`으로 거부하고, 동시에 저장해도 하나만 된다. 이름을 바꾸거나 키를 지우면 그 이름을 다시 쓸 수 있다 | 같은 이름의 키 둘이 생기거나, 지운 키의 이름을 다시 쓰지 못한다 | 흐름 10·5 | L1 |
| KEY-P1 | 플러그인이 `keySlots`로 선언한 키 칸은 관리자 언어의 라벨로 보이고, 저장된 키나 새 키를 넣는다. 새 키는 칸의 서비스 이름으로 넣기와 함께 저장되고, 넣지 못하면 남지 않는다. 플러그인은 넣은 키를 서버에서만 읽고, 바뀌면 `keySlot.changed`로 듣는다. 칸을 비워도 키는 남는다 | 맞춤법 플러그인이 넣은 키를 읽지 못하거나, 키를 바꿔도 옛 키를 쓴다 | 흐름 10·12 | L1 |
