# 요구사항: 본문 형식

상태: 초안 (2026-10-31).

중요도: [기능의 중요도](../features.md)의 mdx "본문을 MDX로 읽고 쓰기(저장했다 다시 열어도 내용이 그대로)"와 "원문 패널, 미리보기", 그리고 `syntax-*`.
흐름이 따로 없다. 읽는 법은 [휴지통](trash.md#읽는-법)과 같다. 번역의 구조 검사는 [번역](translation.md)의 TRANS-N6, 블록 id는 TRANS-B1,
사이트에 그리는 것은 [사이트](site.md)가 다룬다.

## MDX로 읽고 쓰기 🔴

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| FMT-R1 | 글자와 표시는 읽고 다시 써도 같은 뜻이다. 링크와 특수 문자의 이스케이프, 줄바꿈(`<br />`), 빈 줄의 수, 밑줄과 위첨자 같은 표시가 저장할 때마다 바뀌지 않고, 같은 뜻의 다른 표기는 같은 해시가 된다 | 저장할 때마다 본문이 조금씩 바뀌거나, 바뀐 것이 없는데 편집 충돌이 난다 | 코드 · 소유자 확인 (2026-10-31) | L1 |
| FMT-R2 | 블록은 읽고 다시 써도 잃지 않는다. 코드 펜스와 그 메타와 주석, 표(합친 칸, 정렬, 너비), 수식, 그림, 파일, 사이트의 블록과 그 속성, 상자 안의 상자가 그대로다 | 저장했다 다시 열면 코드의 주석이나 표의 합친 칸이 사라진다 | 코드 · 소유자 확인 (2026-10-31) | L1 |
| FMT-R3 | 각주는 참조와 정의를 함께 지키고, 정의 없는 참조도 저장을 거쳐 남는다. 붙여 넣어 중첩된 정의는 맨 위로 옮긴다 | 각주 번호와 내용이 어긋난다 | 코드 · 소유자 확인 (2026-10-31) | L1 |
| FMT-R4 | 읽지 못하는 MDX는 잃지 않는다. 원문을 그대로 두고 그 줄과 칸, 이유(사전의 문구)를 알리며, 동적인 값이나 함수 호출 같은 위험한 표현은 거부한다. 그런 본문도 초안으로는 저장되고 발행만 막힌다 | 문법 하나가 틀려서 본문 전체가 사라진다 | 코드 · 소유자 확인 (2026-10-31) | L1 |
| FMT-R5 | 가져온 `.md`, `.mdx` 파일의 front matter 값을 빠짐없이, 종류 그대로 읽는다(목록은 목록, 날짜는 글자 그대로). 내보낼 때도 같은 값으로 쓴다. 읽은 값을 필드에 맞추는 일은 DATA-I12다 | 가져온 글의 태그가 한 덩어리 글자가 되거나 날짜가 바뀐다 | 코드 · 소유자 확인 (2026-10-31) | L1 |
| FMT-R6 | 저장된 문서의 검사는 MDX 글을 검사할 때와 같은 결과를 낸다. 해시, 문제의 코드, 참조, 글이 같다 | 형식을 바꾼 뒤 발행 검사가 다른 말을 한다 | 코드 · 소유자 확인 (2026-10-31) | L1 |
| FMT-R7 | 내보내는 글은 글 id로 건 링크를 대상의 실제 경로로, 등록된 그림을 공개 주소로 쓴다. 다시 가져올 글이면 id를 지킨다. 가져올 때 `entry:<id>`는 id 링크가 되고 경로는 core가 id로 바꾼다 | 내보낸 글의 링크가 id로 남아 열리지 않는다 | 코드 · 소유자 확인 (2026-10-31) | L1 |
| FMT-R8 | 원문 패널에서 고친 본문은 편집기의 본문이 되고, 다음 저장이 그 본문을 보낸다 | 원문 패널에서 쓴 것이 저장되지 않고 사라진다 | 코드 · 제안대로 (2026-10-31) · 소유자 확인 (2026-10-31) | L3 |

## 형식 플러그인 · 미리보기 · 문법 🟡

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| FMT-P1 | 형식은 플러그인으로 등록하고 옵션과 확장을 검사한다. 가져오기는 블록에 core의 id를 주고 크기 한도를 지키며, 형식이 거부한 글은 읽지 못한 문서로 둔다. MDX를 읽는 부분은 브라우저 번들에 들어가지 않는다 | 형식 플러그인 하나가 깨져 저장이 멈추거나, 관리자 화면이 무거워진다 | 코드 | L1 |
| FMT-P2 | 원문 패널과 미리보기는 같은 본문을 보이고, 읽지 못한 본문은 원문 패널로만 연다 | 미리보기가 저장될 본문과 다르다 | 코드 | L1 |
| FMT-P3 | 관리자 API는 본문을 문서(`doc`)나 형식의 글(`body`와 `format`) 가운데 하나로 받고, 형식 플러그인이 하나도 없어도 문서는 받는다. 읽기에 `?format=`을 주면 작업본과 템플릿의 본문을 그 형식의 글로도 준다 | 어시스턴트나 스크립트가 MDX로 읽고 쓰지 못하거나, 형식 플러그인이 없는 사이트에서 저장이 막힌다 | 코드 | L2 |
| FMT-S1 | 지시문 문법(`syntax-directive`)을 켜면 그 표기로 읽고 쓰며, 등록하지 않은 지시문은 글자로 둔다 | 지시문 문법을 켜거나 끄면 본문이 깨진다 | 코드 | L1 |
| FMT-S2 | 코드 주석 문법(`syntax-shiki`)을 켜면 그 표기로 읽고 쓰고, 다른 도구의 표기를 가져온다 | 코드 블록의 강조가 사라진다 | 코드 | L1 |

## 코드 블록의 주석과 설정 🟡

저장했다 다시 열어도 주석이 같은 것은 FMT-R2(🔴)다. 주석이 뜻한 곳에 걸리는 것과 사이트의 코드 블록 설정은 🟡, 언어마다 주석을 쓰는
문법은 ⚪라 줄이 없다([기능의 중요도](../features.md), 제안대로, 2026-10-31).

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| FMT-C1 | 코드 블록 주석은 쓴 곳에 걸린다. `@char` 규칙(정규식)은 바로 아래 한 줄에, `@document` 규칙은 코드 전체에서 맞는 모든 곳에(g가 없어도) 걸리고, 줄을 넘는 맞음은 줄마다 나눈다. 고르는 것이 없는 `@document`는 코드 전체다. 시작과 `end` 표시는 안쪽부터 닫고, 끝이 없으면 줄 효과는 한 줄, 감싸기는 코드 끝까지다 | 접은 곳이나 줄 효과가 쓴 사람이 뜻한 곳과 다른 줄에 걸린다 | 코드 | L1 |
| FMT-C2 | 사이트에 `codeBlock` 설정이 없으면 모든 도구, 기본 줄 효과 전부, 기본 테마를 쓴다. `lineEffects`는 같은 이름의 기본 효과를 그 자리에서 바꾸고 새 이름은 뒤에 더하며, 그 이름의 주석을 읽고 쓴다 | 사이트가 더한 줄 효과가 저장되지 않거나, 설정 없는 사이트에서 코드 도구가 사라진다 | 코드 | L1 |
