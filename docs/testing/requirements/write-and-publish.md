# 요구사항: 글 쓰고 발행

상태: 초안 (2026-10-31).

흐름: [흐름 1 · 글 쓰고 발행하기](../../design/admin/flows/01-write-and-publish.md). 중요도: [기능의 중요도](../features.md)의 "1 글 쓰고 발행".
읽는 법은 [휴지통](trash.md#읽는-법)과 같다.

본문을 저장 형식(MDX)으로 쓰고 다시 읽어도 같은지는 이 표가 아니라 본문 형식의 표에서 다룬다(`mdx`, `blocks` 패키지). 블록 id가
저장을 거쳐도 남는지는 [번역](../features.md)의 표에서 다룬다. 블록마다 원문을 표시하는 데 쓰이기 때문이다.

## 찾은 것

### 정한 것 (소유자, 2026-10-31)

- **공개 서비스의 방어 테스트는 남긴다.** `content-service.test.ts`의 "10. Service Input Structural & Accessor Defenses"와 "rejects non-exact
  service inputs" 같은 테스트 13개는 getter, symbol, 다른 prototype을 가진 입력을 막는지 본다. HTTP로는 JSON만 들어오지만, 사이트의 서버 코드가
  `@monti-cms/core/server`의 서비스를 직접 부르면 이런 입력이 생긴다. 그때 잘못된 값을 저장하지 않고 오류로 알리는 것을 지킨다(WRITE-S7).

### 변이 테스트 (2026-10-31)

| 코드 | 잡음 / 전체 | 살아남은 것 |
|---|---|---|
| `domain/publish.ts` | 90 / 96 (93.8%) | 개발자만 보는 오류 글자 5개. 참조를 합칠 때 같은 참조의 자리를 하나 덜 적는 바꿈 1개(할 일 목록의 자리만 준다) |
| `domain/slug-address.ts` | 54 / 56 (96.4%) | 개발자만 보는 오류 글자와, 없는 주소에서만 다른 `?.` 하나 |
| `snapshot.ts`의 `validateForPublish` | 153 / 198 (77.3%) | 아래 둘을 고친 뒤 남은 것은 할 일이 가리키는 자리(`path`, `position`)와, 본문과 관계 필드가 같은 글을 함께 가리킬 때의 드문 경우다 |
| `store/lifecycle.ts` | 81 / 96 (84.4%) | 아래 둘을 고친 뒤 남은 것은 결과가 같은 바꿈, 알림 문구의 "폴더를 다시 만듦", 코드가 잘못 불렀을 때만 다른 검사다 |

새로 더한 테스트 넷. 각 테스트에 결함을 손으로 넣어 실패하는 것을 확인했다.

- **이미지가 있는 글을 하나도 발행하지 못하는 바꿈**을 아무 테스트도 잡지 못했다. 미디어가 있는 이미지로 발행이 준비되는지를 더했다(WRITE-P1).
- **주소로 건 본문 링크를 검사하는 코드**를 아무 테스트도 실행하지 않았다. 없는 글로 가는 링크는 막고, 공개되지 않은 글로 가는 링크는
  알리기만 하는지를 더했다(WRITE-P1).
- **보관, 보관 풀기, 복원이 버전을 올리지 않는 바꿈**을 잡지 못했다. 그러면 옛 버전으로 보낸 쓰기가 통과해 다른 곳의 변경을 덮는다. 단계마다
  버전이 하나씩 오르고 옛 버전이 거부되는지를 더했다(WRITE-S2).
- **원문 하나를 복원할 때 함께 버린 번역을 찾지 않는 바꿈**을 잡지 못했다. 번역이 휴지통에 남는다. 원문과 함께 돌아오는지를 더했다(TRASH-R2).

### 변이 테스트: 편집기 상태 (2026-10-31)

`admin`의 `entry-editor-store.ts`: 312 / 460 (67.8%). 살아남은 것은 대부분 성능을 위한 캐시와 알림, 오류 문구, 저장이 이어서 한 번 더 도는
동안만 보이는 상태, 코드가 잘못 불렀을 때만 다른 검사, 결과가 같은 분기다. 사용자가 겪는 셋에 테스트를 더했고, 각각 결함을 손으로 넣어
실패하는 것을 확인했다.

- **편집 충돌 중에 입력하면 충돌 상태가 풀리는 바꿈**: 그러면 저장이 다시 나간다. 입력해도 충돌이 남고 아무것도 보내지 않는지를 더했다(WRITE-C1).
- **서버 판을 불러온 뒤에도 임시 저장본 알림이 남는 바꿈**(WRITE-R2).
- **서버에 닿지 못한 다시 시도가 상태를 바꾸지 않는 바꿈**: 고친 것이 브라우저에만 있다는 표시가 사라진다(WRITE-S5).

### ID를 달지 않은 테스트

- **본문 형식**: `mdx`의 `roundtrip`, `editor-roundtrip`, `standard-write`. 본문 형식의 표에서 다룬다.
- **블록 id**: `store-contract.entries`의 "block ids in the store", `content-service`의 "9. Block ids", `entries-doc`의 블록 id. 번역의 표에서 다룬다.
- **다른 기능**: 상태 바꾸기, 복제, 영구 삭제(`entry-editor-store`의 "status changes, duplicate and delete"), 언어 탭과 원문 패널(번역), 목록
  조회와 거르기(`http/entries`의 GET), 사이드 패널(플러그인).
- **React 배관**: `entry-editor-store`의 "snapshot and view", `use-entry-editor`의 "selectors". 고친 값 하나가 화면 전체를 다시 그리지 않는지를
  본다. 약속이라기보다 구현이지만, 깨지면 긴 글에서 입력이 느려진다. 그대로 둔다.
