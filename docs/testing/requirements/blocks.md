# 요구사항: 블록

상태: 초안 (2026-10-31).

중요도: [기능의 중요도](../features.md)의 blocks "블록을 사이트에 렌더링하기"와 "블록 편집기". 흐름이 따로 없다. 읽는 법은 [휴지통](trash.md#읽는-법)과 같다.
core가 블록을 그리는 공통 규칙(모르는 블록, 맞지 않는 속성)은 [사이트](site.md)의 SITE-R1, D4가 다룬다.

## 사이트에 그리기 🔴

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| BLOCK-R1 | 블록 패키지의 블록(상자, 탭, 열, 강조, 툴팁 등)의 내용과 속성은 저장된 문서와 MDX 어느 쪽으로 그려도, 서버와 브라우저 어디서 그려도 똑같이 전달된다. 모양(CSS, 컴포넌트)은 블로그 주인이 정한다 | 같은 글의 블록이 미리보기와 사이트에서 다른 내용으로 나온다 | 코드 · 소유자 확인 (2026-10-31) | L1 |
| BLOCK-R2 | 차트, 머메이드, 코드 탐색기는 정의를 읽어 그리고, 읽지 못하면 페이지 대신 그 블록에 이유를 보인다 | 차트 하나의 오타로 글 전체가 깨진다 | 코드 · 소유자 확인 (2026-10-31) | L1 |
| BLOCK-R3 | 코드 참조(code-ref)는 그 라벨이 있는 코드 블록의 줄로 이어진다 | 본문의 코드 참조가 엉뚱한 줄을 가리킨다 | 코드 · 소유자 확인 (2026-10-31) | L1 |
| BLOCK-R4 | 블록 정의는 이름, 속성, 사전의 라벨, 타입을 갖고, 가벼운 진입점은 무거운 그리기 코드를 끌어오지 않는다 | 블록 하나를 쓰려다 사이트의 번들이 커진다 | 코드 · 소유자 확인 (2026-10-31) | L1 |
