# 요구사항: 미디어

상태: 초안 (2026-10-31).

흐름: [흐름 6 · 미디어](../../design/admin/flows/06-media.md). 중요도: [기능의 중요도](../features.md)의 "6 미디어". 읽는 법은 [휴지통](trash.md#읽는-법)과 같다.
파일과 폴더를 지우는 것은 [휴지통](trash.md)의 TRASH-T5(쓰는 파일은 남김), TRASH-D1과 D8(영구 삭제)이 다룬다.

## 찾은 것

### 변이 테스트 (2026-10-31)

모듈을 읽을 때 한 번만 도는 코드의 바꿈은 뺐다.

| 코드 | 잡음 / 전체 | 살아남은 것 |
|---|---|---|
| `store/media.ts` | 345 / 399 (86.5%) | 아래를 고친 뒤 남은 것은 개발자만 보는 문구, 개수의 `?? 0`, 정리할 상태의 목록, 실패 표시(`failMediaAsset`)다 |
| `services/media-service.ts` | 44 / 47 (93.6%) | 시계의 출처와 로그 문구 |
| `core/media-types.ts` | 77 / 88 (87.5%) | 설정 오류의 문구, 텍스트를 엿보는 길이의 경계 |
| `http/v1/media/upload-flow.ts` | 123 / 174 (70.7%) | 아래를 고친 뒤 남은 것은 개발자만 보는 문구와, 원본 형식을 미리 거부하는 길이다(준비할 때 이미 거른다) |
| `http/v1/media/media-files.ts` | 100 / 158 (63.3%) | 아래를 고친 뒤 남은 것은 형식 이름 문구, 완료할 때 한 번 더 보는 크기와 첨부 형식 검사다. 준비할 때 이미 거르고, 말한 크기보다 큰 파일은 따로 막는다 |

새로 더한 테스트. 각각 결함을 손으로 넣어 실패하는 것을 확인했다.

- **원본 파일**: 올리기를 끝낼 때 원본을 저장소로 옮기는 코드를 아무 테스트도 실행하지 않았고, 저장소가 원본의 칸을 적지 않아도 몰랐다(MEDIA-U3).
- **실제 내용 검사**: 그림이 아닌 내용을 거부하는 코드를 아무 테스트도 실행하지 않았다(MEDIA-U2).
- **이미 실패한 업로드를 완료로 받는 바꿈**(MEDIA-U2), **올릴 폴더를 넘기지 않는 바꿈**(MEDIA-U3).
- **저장소의 두 번째 쪽 목록과 이름 바꾸기**(NFC로 맞춤)를 저장소에서 확인하는 테스트가 없었다(MEDIA-B1, B4).
