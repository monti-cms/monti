# 요구사항: 어시스턴트

상태: 초안 (2026-10-31).

흐름: [흐름 2 · 어시스턴트](../../design/admin/flows/02-assistant.md). 중요도: [기능의 중요도](../features.md)의 "2 어시스턴트" 🟡. 🟡라서 대표 약속만
적는다. 글 화면의 필드 채우기, 에이전트의 쓰기(#311), 어시스턴트 패널(#310)의 약속이다. 제안의 검토와 적용 화면은 #312~#314에서 더한다. 채우기 단추가 누른 때의 글을 읽고, 실패와
빈 결과에 아무것도 쓰지 않는 것은 [관리자 플러그인](plugins.md)의 PLUG-A3, API 키는 [API 키](keys.md)가 다룬다. 읽는 법은 [휴지통](trash.md#읽는-법)과 같다.

## 필드 채우기 🟡

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| ASSIST-F1 | 필드의 "채우기"로 넣은 값은 사람이 그 값을 고치거나 글을 저장할 때까지 "AI 제안"으로 표시된다. 채우지 않은 필드에는 표시가 없다. 플러그인은 같은 표시를 공개 훅(`useField`의 `assisted`)으로 읽는다 | 사람이 읽지 않은 AI의 글을 사람이 쓴 것으로 알고 발행한다 | 흐름 1·07 · 제안대로 (2026-10-31) | L3 |

## 에이전트의 쓰기 🔴

에이전트가 사이트를 바꾸는 길이다([관리자 에이전트 설계](../../design/agent.md) 3절). 에이전트는 바꾸지 않고 계획만 하고, 사람이 받으면 적용하며, 적용한 것은 되돌린다.

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| AGENT-W1 | 쓰기 기능의 계획은 아무것도 바꾸지 않고, 바뀔 자리마다 지금 값과 바꿀 값을 하나씩 낸다. 바뀌지 않을 자리는 빼고, 없는 필드는 거부한다. 적용하면 화면의 저장과 같은 길로 바뀌고 그 관리자의 변경으로 남으며, 되돌리면 이전 값으로 돌아간다 | 받기 전에 글이 바뀌거나, 적용이 검사를 건너뛰거나, 되돌릴 수 없다 | 설계 3·6절 | L2 |
| AGENT-W2 | 계획한 뒤 그 자리가 바뀌었으면 적용을 거부하고(`conflict`) 사람이 쓴 것을 남긴다. 한 글의 다른 필드 둘은 차례로 적용된다 | 사람이 그사이 고친 것을 에이전트가 덮어쓴다 | 설계 5절 "그사이 바뀐 자리" · 소유자 결정 (2026-11-02) | L2 |
| AGENT-W3 | 폴더 옮기기와 휴지통 보내기도 같은 길로 적용되고 되돌려진다. 휴지통에서 되돌리면 글이 돌아온다 | 옮긴 글이나 버린 글을 되돌릴 수 없다 | 설계 6절 · 흐름 2·11~16 | L2 |
| AGENT-W4 | 쓰기는 한 번에 실행되지 않는다. 바로 실행하라는 요청은 거부되고, 읽기는 계획할 수 없다 | 에이전트가 제안을 거치지 않고 사이트를 바꾼다 | 설계 원칙 4 | L2 |
| AGENT-P1 | 에이전트의 쓰기 도구는 사이트를 바꾸지 않고, 그 실행의 제안 하나에 항목을 더한다(그 요청을 인용한다). 같은 실행의 뒤 읽기는 그 항목이 적용된 것처럼 본다. 바뀔 것이 없거나 할 수 없는 쓰기는 제안을 만들지 않고 이유를 답한다 | 에이전트가 받기 전에 사이트를 바꾸거나, 앞 단계를 모르고 계획한다 | 설계 3·4절 | L1 |
| AGENT-E1 | 쓰기를 부른 요청이 끝나면 제안이 저장되고, 패널로 가는 답에 제안이 실리며, 저장된 대화에도 그때 모습으로 남는다 | 다시 연 대화에서 제안이 사라지거나, 패널이 제안을 모른다 | 설계 4·5절 · 흐름 2·26 | L1 |
| AGENT-A1 | 적용은 넣은 항목을 차례로 하나씩, 에이전트가 한 변경으로 기록하며 하고, 걸음마다 진행을 알린다. 하나가 실패해도 나머지는 하고, 실패는 이유와 함께 남는다. 끊긴 뒤 다시 적용하면 남은 것만 한다 | 일부 실패에 전체가 멈추거나, 끊긴 적용을 다시 하면 두 번 바뀐다 | 설계 6절 · 흐름 2·14~15 | L1 |
| AGENT-A2 | 뺀 항목과, 계획한 뒤 대상이 바뀐 항목은 적용하지 않는다. 검토를 열 때 그사이 바뀐 항목은 "이 사이에 고쳐짐"으로 표시된다 | 사람이 고친 것을 덮어쓰거나, 뺀 것이 적용된다 | 설계 5절 · 흐름 2·12~13 | L1 |
| AGENT-A3 | 되돌리기는 적용한 항목을 거꾸로 되돌리되, 적용한 뒤 사람이 바꾼 항목은 그대로 둔다 | 되돌리기가 사람이 나중에 쓴 것을 지운다 | 소유자 결정 (2026-11-02) · 흐름 2·16 | L1 |
| AGENT-A4 | 버리기는 아무것도 바꾸지 않고 제안을 "버림"으로 닫는다. 닫힌 제안은 적용할 수 없다 | 버린 제안이 적용된다 | 소유자 결정 (2026-11-02) | L1 |

## 어시스턴트 패널 🟡

빈 패널, 대화, 지난 대화다. 흐름 2의 01, 02, 06, 10, 25다. 화면의 모양은 Storybook 스토리(`Screens/AI/Assistant panel`)가 본다.

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| ASSIST-P1 | 빈 패널은 지금 화면의 기본 요청("이 목록에서")과 최근에 물은 것을 보이고, 하나를 누르면 그 말로 묻는다. 도구 줄은 한 일을 말로 적는다("글 목록 읽음 · 게시글 148편") | 무엇을 물을지 몰라 패널을 닫거나, 도구 줄이 `entries.list` 같은 이름만 보인다 | 흐름 2·01~02 | L3 |
| ASSIST-P2 | 목록에서 고른 행은 입력란 위에 칩("고른 글 2편")으로 보이고 요청과 함께 간다. ×로 빼면 그다음 요청에는 가지 않는다 | 고른 글이 아닌 다른 글에 대해 답하거나, 뺀 글이 계속 간다 | 흐름 2·10 | L3 |
| ASSIST-P3 | 하다가 끊기면 한 일은 남고 멈춘 도구 줄은 "여기서 멈춤"이 된다. "이어서 하기"는 같은 대화를 사람의 새 말 없이 이어 간다 | 끊긴 일을 처음부터 다시 하거나, 어디까지 했는지 모른다 | 흐름 2·06 | L3 |
| ASSIST-H1 | 지난 대화는 패널 안에 날짜별로 보이고, ⋯에서 지우면 목록에서 빠진다 | 지운 대화가 남거나 다른 대화가 지워진다 | 흐름 2·25 | L3 |
| ASSIST-H3 | 지난 대화의 행은 그 대화의 마지막 제안으로 결과를 말한다: 검토 대기, 적용 N건, 되돌림, 버림. 제안이 없던 대화는 말하지 않는다 | 무엇을 했던 대화인지 모르거나, 기다리는 제안을 잊는다 | 흐름 2·25 | L1 |
| ASSIST-R1 | 대화 안의 제안 카드는 바뀌는 묶음을 보이고(새 글만 있는 카드는 파일 셋까지, 나머지는 "상세 보기"로), 적용하면 적용한 수와 못 한 수, 못 한 이유를 보이며, "모두 되돌리기"로 되돌린다 | 제안을 적용하거나 되돌릴 길이 없거나, 못 한 항목을 모르거나, 카드에 안 보이는 파일을 볼 길이 없다 | 흐름 2·11, 16 | L3 |
| ASSIST-R2 | 검토 화면은 항목마다 체크를 두고, 뺀 항목을 서버에 남기며, 넣은 항목만 적용한다. 그사이 바뀐 항목은 빠진 채 "이 사이에 고쳐짐"으로 보인다 | 뺀 항목이 적용되거나, 사람이 고친 자리가 덮어써진다 | 흐름 2·12~13 | L3 |
| ASSIST-H2 | 안 연 대화는 설정한 날수(처음은 30일)가 지나면 지워진다. 다시 열거나 이어서 물은 대화는 그날부터 다시 센다. "지우지 않음"이면 남는다. 다른 관리자의 대화는 지우지 않는다 | 보던 대화가 사라지거나, 대화가 끝없이 쌓인다 | 흐름 2·25 | L1 |
