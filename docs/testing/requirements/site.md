# 요구사항: 사이트가 글을 보여 주기

상태: 초안 (2026-10-31).

중요도: [기능의 중요도](../features.md)의 "사이트가 글을 보여 주기(렌더링, 공개 조회)". 흐름이 따로 없는 core의 기능이다. 읽는 법은 [휴지통](trash.md#읽는-법)과 같다.
본문을 MDX로 읽고 쓰는 것은 본문 형식의 표(다음에 만든다), 발행본만 공개되는 것은 [글 쓰고 발행](write-and-publish.md)의 WRITE-P3이 다룬다.

## 그리기와 읽기 🔴

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| SITE-R1 | 본문은 저장된 문서만으로 그린다(MDX를 다시 컴파일하지 않는다). 문서가 아니거나 모르는 노드, 맞지 않는 속성이 있어도 오류를 내지 않고 대체 컴포넌트로 그리며 알린다. 개발에서만 표시하고, strict 모드는 오류를 낸다 | 글 하나의 이상한 블록 때문에 페이지 전체가 깨진다 | 코드 | L1 |
| SITE-R2 | 링크는 안전한 주소만 쓴다. `javascript:`, `data:`, `//다른 곳`, 공백이나 제어 문자를 섞은 것은 href를 버리고, 외부 링크는 새 창으로 연다 | 글의 링크 하나로 방문자의 브라우저에서 스크립트가 돈다 | 코드 | L1 |
| SITE-R3 | 글 id로 건 링크는 대상의 지금 주소로 그리고, 독자의 언어를 따르며, 대상에 번역이 없으면 원문으로 간다. 대상이 발행되지 않았으면 그냥 글자로 그린다 | 주소를 바꾼 글로 가는 링크가 모두 끊긴다 | 코드 | L1 |
| SITE-R4 | 그림과 파일은 그 글이 가진 미디어 참조로 그린다(주소, 크기, 너비). 준비되지 않은 미디어는 이유를 남기고, 사이트의 그림 resolver가 있으면 그것이 이긴다 | 글의 그림이 깨지거나 다른 글의 그림이 나온다 | 코드 | L1 |
| SITE-R5 | 공개 조회는 목록을 데이터베이스에서 쪽으로 나누고 정렬하며 초안을 뺀다. 관계는 발행된 대상의 제목과 주소로, 옛 주소는 새 주소로 가라고 알리고, 지운 필드의 값은 빼며, 번역은 발행된 언어와 원문 대체를 준다 | 사이트에 초안이나 지운 필드의 값이 나온다 | 코드 | L2 |
| SITE-R6 | 미리보기는 관리자에게만 초안을 보인다. 공개 조회는 그때도 발행본을 보인다 | 방문자가 쓰는 중인 글을 본다 | 흐름 1·15 | L2 |
| SITE-R7 | 본문 형식을 고르면 본문을 글로도 준다. 발행된 대상의 링크는 실제 경로로, 그림은 공개 주소로, 발행되지 않은 대상은 링크가 아닌 글자로 쓴다 | 피드나 검색용 글에 깨진 링크가 들어간다 | 코드 | L2 |

## 그리기의 세부 🟡

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| SITE-D1 | 사이트는 제목, 링크, 표시, 목록, 표, 블록의 컴포넌트를 바꿀 수 있고, core, 확장, 사이트 순으로 덮는다. 컴포넌트의 props는 블록 정의에서 타입이 나온다 | 사이트가 컴포넌트를 바꿨는데 기본 모양이 나온다 | 코드 | L1 |
| SITE-D2 | 코드 블록은 언어, 제목, 주석을 그리고, 불러오지 않은 언어나 주석을 달 수 없는 코드는 글자로 보이며 실패하지 않는다. 사이트의 테마와 언어를 쓴다 | 코드 블록 하나 때문에 페이지가 깨진다 | 코드 | L1 |
| SITE-D3 | 목차는 제목 2~3단계를 문서 순서로, 같은 제목은 -1, -2로 앵커를 단다. 각주는 처음 참조 순서로 번호를 매기고, 정의 없는 참조는 쓴 그대로 둔다. 수식은 KaTeX로 그리고 읽지 못하면 그대로 보인다 | 목차의 링크가 다른 제목으로 간다 | 코드 | L1 |
| SITE-D4 | 블록의 속성은 평평한 props로 넘기고, 허용되지 않은 선택은 기본값으로 바꾼다. 사이트의 블록은 이름, 문법, 컴포넌트, 자식을 검사한 뒤 플러그인 블록 다음에 더한다. 블록의 라벨은 관리자 언어의 사전에서 온다 | 잘못 정의한 블록이 조용히 무시된다 | 코드 | L1 |
| SITE-D5 | 공개 스타일(`render.css`)은 정렬, 할 일 목록, 어두운 코드 색을 지키고, 그린 목록에는 모두 key가 있다 | 다크 모드에서 코드가 안 보인다 | 코드 | L1 |

## Next.js와 SEO 🟡

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| SITE-N1 | Next.js 연결은 API 경로를 나눠 받고(모르는 경로는 404, 다른 메서드는 405), 관리자 페이지를 Next의 라우터로 움직이며, 로그인하지 않은 사람은 로그인으로 보낸다. `basePath`를 넘기고, 설정 파일이 브라우저 번들에 들어가면 개발 중에 알린다. 미리보기 도우미는 관리자에게만 초안을 준다 | 배포한 뒤 관리자 화면이나 API가 404가 된다 | 코드 | L1 |
| SITE-N2 | SEO 필드는 역할로 찾고, 빈 제목과 설명은 제목과 요약을 따른다. 관리자 화면은 그 따름을 보이고, AI 제안을 그 필드에 붙인다 | 검색 결과에 빈 제목이 나온다 | 흐름 1·8 | L1 |

## 찾은 것

### 변이 테스트 (2026-10-31)

모듈을 읽을 때 한 번만 도는 코드의 바꿈은 뺐다.

| 코드 | 잡음 / 전체 | 살아남은 것 |
|---|---|---|
| `render/components/link.tsx` | 43 / 57 (75.4%) | 아래를 고친 뒤 남은 것은 결과가 같은 바꿈(사이트 주소로 풀지 않아도 같은 주소로 남는다)과 `http`를 외부 링크로 보는 조건이다 |
| `render/document/attributes.ts` | 46 / 82 (56.1%) | 불리언과 선택 속성의 기본값을 고르는 조건. 맞지 않는 값은 SITE-R1의 테스트가 대체로 그리는 것을 본다 |
| `render/document/render.tsx` | 410 / 767 (53.5%) | 그리기는 React 안에서 돌아서 Stryker가 테스트와 줄을 이어 주지 못하는 곳이 있다. "아무 테스트도 실행하지 않음"으로 나온 raw HTML의 대체(560행)는 손으로 넣어 보면 테스트가 잡는다. 표시 컴포넌트가 없을 때의 대체(186행)는 정말 테스트가 없지만, 사이트에는 같은 글자가 나온다 |
| `read/index.ts` | 203 / 346 (58.7%) | 미디어 크기와 파일 정보의 `?? null`, 언어 대체의 세부, 관리자 미리보기의 본문 글(`workingLink`)이다. 미리보기는 관리자만 본다 |

새로 더한 테스트: **새 창으로 여는 외부 링크의 `rel="noreferrer noopener"`를 빼는 바꿈**을 잡지 못했다. 그러면 열린 페이지가 원래 탭을 조종할 수 있다(SITE-R2).
