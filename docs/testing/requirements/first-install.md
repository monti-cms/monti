|---|---|---|---|---|
| AUTH-A1 | 첫 관리자는 계정이 하나도 없을 때만 만든다. 하나가 생기면 다른 이메일로 시도해도 거부하고, 동시에 둘이 시도하면 하나만 된다 | 누구나 /admin에 들어와 관리자 계정을 하나 더 만든다 | 흐름 8·1, 8·4 | L1 |
| AUTH-A2 | 만들면 같은 자격으로 바로 로그인해 관리자 화면으로 보낸다 | 만든 직후 다시 로그인해야 한다 | 흐름 8·3 | L1 |
| AUTH-A3 | 이메일 형식, 10자 이상, 두 비밀번호가 같은지 검사하고, 맞지 않으면 아무것도 만들지 않는다 | 잘못 친 비밀번호로 관리자가 만들어진다 | 흐름 8·2 | L1 |
| AUTH-A4 | 로그인 화면은 관리자가 없으면 첫 관리자 폼을, 있으면 로그인 폼을 보이고, 지난 시도가 왜 안 됐는지 말한다 | 처음 설치한 사람이 들어갈 길을 찾지 못한다 | 흐름 8·1, 8·5, 8·6 | L3 |

## 로그인 🔴

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| AUTH-L1 | 비밀번호는 해시마다 다른 솔트로 저장하고 원문을 남기지 않는다 | 데이터베이스가 새면 비밀번호도 샌다 | 코드 | L1 |
| AUTH-L2 | 맞는 비밀번호만 관리자 세션을 준다(이메일의 대소문자는 가리지 않는다). 틀린 비밀번호와 없는 이메일은 같은 방식으로 거부하고, 이유와 함께 로그인 화면으로 돌려보낸다 | 없는 이메일인지 틀린 비밀번호인지로 계정을 알아낸다 | 흐름 8·6 | L1 |
| AUTH-L3 | 한 이메일로 5번 틀리면 1분 동안 막고, 한 주소는 더 많이 틀려야 막는다. 기다리면 풀리고, 맞는 비밀번호나 재설정은 횟수를 지운다. 모든 인스턴스가 같은 횟수를 쓰고, 없는 이메일들은 한 횟수를 나눠 쓴다 | 비밀번호를 끝없이 맞혀 본다 | 흐름 8·7 | L1 |
| AUTH-L4 | GitHub 로그인은 시작한 곳의 state를 확인하고, 변조된 세션을 거부하며, 다른 사이트의 POST를 막는다. 로그아웃은 세션을 지운다 | 다른 사람의 로그인으로 들어온다 | 흐름 8·5 | L1 |
| AUTH-L5 | 관리자는 `provider:id`로만 판정한다. 바뀔 수 있는 로그인 이름은 받지 않고, 한 provider의 관리자는 다른 provider의 관리자가 아니다 | GitHub 이름을 바꿔 남의 관리자가 된다 | 흐름 8·9 | L1 |
| AUTH-L6 | 세션은 `MONTI_SECRET`에서 나온 키로 서명한다. 다른 비밀로는 읽을 수 없고, 비밀이 없으면 그 이름을 대며 시작하지 않는다 | 세션을 위조한다 | 코드 | L1 |
| AUTH-L7 | 개발용 우회는 개발 중에, 이 컴퓨터에서 직접 온 요청에만 된다. 프로덕션이나 배포된 것처럼 보이는 곳에서는 무엇을 설정해도 되지 않는다 | 배포된 사이트에 로그인 없이 들어간다 | 코드 | L1 |
| AUTH-L8 | 믿지 않는 호스트로는 로그인하지 못한다. `AUTH_URL`이 있으면 그 주소로 고정하고, 프로덕션에서 믿을 호스트가 없으면 알린다 | 가짜 호스트로 돌아오는 주소를 만들어 세션을 가로챈다 | 코드 | L1 |
| AUTH-L9 | 로그인 설정은 정해진 환경 변수에서 읽고, 빠진 것과 어디서 왔는지를 말하되 값은 출력하지 않는다 | 비밀값이 로그에 찍힌다 | 코드 | L1 |
| AUTH-L10 | 로그인 방법이 설정되지 않으면 관리자 화면 대신 설정이 필요하다는 화면을 보이고, 방문자에게는 오류의 내용을 숨긴다 | 설정 오류의 세부가 방문자에게 보인다 | 흐름 8·10 | L3 |
| AUTH-L11 | 비밀번호를 잊으면 `monti reset-password`로 바꾼다. 바꾸면 옛 비밀번호는 안 되고, 계정이 없는 이메일과 짧은 비밀번호는 거부한다. `monti doctor`는 관리자가 아직 없다고 알린다 | 비밀번호를 잊은 관리자가 사이트에 들어가지 못한다 | 소유자 결정 | L1 |

## 로그인 연결 🟡

## 찾은 것

### 변이 테스트 (2026-10-31)

모듈을 읽을 때 한 번만 도는 코드의 바꿈은 뺐다. auth 패키지에 core와 같은 변이 테스트 설정(`packages/auth/stryker.config.mjs`)을 붙였다.

| 코드 | 잡음 / 전체 | 살아남은 것 |
|---|---|---|
| `auth/password.ts` | 159 / 195 (81.5%) | 아래를 고친 뒤 남은 것은 문구, 저장소가 이미 막는 두 번째 첫 관리자(같은 키를 버전 0으로만 쓴다), 실패 횟수의 정리 경계다 |
| `auth/password-hash.ts` | 47 / 56 (83.9%) | 비용 값의 검사와, 길이가 다를 때 비교 대신 오류가 나는 바꿈(어느 쪽이든 들어가지 못한다) |
| `auth/auth.ts` | 282 / 421 (67.0%) | 설정 오류와 경고의 문구, 한 번만 남기는 로그, 요청 주소를 다시 맞추는 정규화. 믿지 않는 호스트는 Auth.js가 먼저 거부하므로(AUTH-L8의 "an untrusted host cannot sign in"이 잡는다) 정규화는 두 번째 방어선이다 |
| `auth/admins.ts` | 52 / 79 (65.8%) | 아래를 고친 뒤 남은 것은 문구와 앞뒤 공백을 지우는 것이다 |
| `auth/github.ts`, `provider.ts` | 75 / 94 | 문구, 숫자가 아닌 id에서 오류가 나는 바꿈(관리자가 되지 않는다) |
| core `adapters/auth/auth-gateway.ts` | 98 / 134 (73.1%) | 한 번만 남기는 경고와 문구. 숫자가 아닌 id는 뒤의 비교에서 오류가 난다 |
| core `adapters/auth/dev-bypass.ts` | 72 / 82 (87.8%) | 아래를 고친 뒤 남은 것은 대괄호와 `::ffff:`를 벗기는 정규식, 포트를 떼는 경계다 |
| core `adapters/auth/trust-host.ts`, 세션 라우트 | 92 / 93 | 문구 하나 |

새로 더한 테스트. 각각 결함을 손으로 넣어 실패하는 것을 확인했다.

- **`auth()`의 관리자 목록에 다른 provider로 적은 관리자가 첫 provider의 같은 id를 관리자로 만드는 바꿈**을 auth의 테스트 79개가 하나도 잡지 못했다(AUTH-L5).
- **첫 계정을 쓰다 실패하면 첫 관리자 자리를 다시 여는 코드**를 아무 테스트도 실행하지 않았다. 깨지면 처음 설치가 영영 잠긴다(AUTH-A1).
- **정확히 가장 짧은 길이의 비밀번호**를 받는지 보는 테스트가 없었다(AUTH-A3).
- **`127.0.0.1.example.com`, `x127.0.0.1` 같은 이름을 이 컴퓨터로 보는 바꿈**을 잡지 못했다. 개발용 우회가 남의 요청에 열린다(AUTH-L7).

### 캔버스와 대조 (2026-10-31)

AUTH-L3에 보드의 숫자(5번, 1분)를 적었다. 코드도 같다(`MAX_FAILURES = 5`, 1분). 관리자가 아닌 계정의 "다른 계정으로 로그인"(AUTH-A5)은 지금 "로그아웃"과 계정 id(`github:12345`)를 보여서 층이 `—`다. #320이 만든다.
흐름 문서의 단추 이름 "만들기"를 보드의 "생성"에 맞췄다.

### admin 코드와 보드 대조 (2026-10-31)

로그인 화면의 나머지 차이(단추 이름 "생성", 칸 아래의 오류, 잠김을 알리는 문구, 빈 목록의 "템플릿으로 쓰기")는 #320에 있다. 첫 관리자 폼이 오류를 하나씩만 돌려보내는 것(AUTH-A6)과 계정 id를 보이는 것은 #320에 더했다.
