🔴 기능은 모두 표가 있다. 본문 형식, 블록, API 키는 변이 테스트를 아직 돌리지 않았다.

모두 테스트가 놓친 결함이었다. 코드 자체가 틀린 곳은 아직 나오지 않았다. 각 테스트는 그 결함을 소스에 손으로 넣어 실패하는 것을 확인했다.

## 캔버스와 대조 (2026-10-31)

표는 저장소의 흐름 문서에서 만들었다. 그 뒤 디자인 캔버스의 보드 162개를 표와 견줬다. 보드와 어긋나게 쓴 줄을 고치고(예: WRITE-P1의
꾸밈용 그림, SCHEMA-D2의 "글을 남기는 선택은 없다", LIST-F2의 필터 칩), 보드에는 있고 코드에는 아직 없는 약속을 층 `—`로 더했다.
흐름 문서가 보드와 다른 곳은 문서를 보드에 맞췄다. 각 표의 "캔버스와 대조"에 무엇을 고쳤는지 있다.

캔버스에서 고칠 것: 흐름 5 단계 26·27의 숫자가 맞지 않고, 흐름 5 페이지 제목과 흐름 7 단계 제목(필터 칩)이 낡았다.

## admin 코드와 보드 대조 (2026-10-31)

표와 보드를 견준 뒤, admin 코드와 보드를 직접 견줬다(흐름 1, 3~9). 차이는 54곳이었다. 표가 지금 코드를 받아 적어 보드와 어긋난 줄이 10곳,
이미 이슈에 있던 차이가 27곳, 어디에도 적히지 않은 차이가 17곳이다. 흐름 4는 차이가 없었다. 원칙:

- 지금의 동작을 지키는 줄과 테스트는 남긴다. 보드의 동작은 층 `—`인 줄로 더하고 이슈를 가리킨다. 그 이슈가 들어올 때 함께 바꿀 테스트는
  각 표의 "admin 코드와 보드 대조"에 이름을 적었다.
- 적히지 않은 차이는 맞는 이슈에 적었다(#278, #280, #317~#322, #324, #325, #369). 대표 이미지의 대체 텍스트는 새 이슈 #373이다.
- 이슈에 남아 있던, 이미 해결된 줄도 그 이슈에 적었다.

소유자가 정한 것(2026-10-31): 빈 요약은 보드대로 발행을 막는 할 일이다(WRITE-P10, #375).

## 테스트가 막는 것이 아니라 이슈로 간 것

- #369: 영구 삭제를 막는 규칙을 core와 admin이 따로 계산한다.
- #322, #323, #278, #279: 흐름에는 있고 코드에는 아직 없는 약속. 이슈의 완료 기준에 ID를 적었다.
