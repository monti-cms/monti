# 요구사항: 관리자 화면의 부품

상태: 초안 (2026-11-01).

중요도: [기능의 중요도](../features.md)의 ui "관리자 화면의 부품" 🟡. 모양(클래스, 크기, 색, 자리)은 시각 회귀(`packages/ui/visual`)가 보고, 이 표는
스크린숏이 보지 못하고 관리자가 기대는 것만 적는다. 부품의 역할과 이름, 키보드와 포커스, 부품이 알리는 값과 거부하는 것, 시각 회귀와 디자인 검사가
쓰는 도구다. 관리자 화면의 테스트는 모두 역할과 이름으로 부품을 찾으므로, 부품이 역할을 잃으면 관리자와 화면 읽기가 함께 깨진다. 기기마다 기억하는
값이 막힌 저장소에 깨지지 않는 것은 [관리자의 바탕](admin.md)의 ADMIN-S1이 맡는다. cmdk 메뉴의 거르기와 기억하는 패널 너비는 ⚪라 줄이 없다.
흐름이 따로 없다. 읽는 법은 [휴지통](trash.md#읽는-법)과 같다.

## 디자인 도구 🟡

시각 검사기(UI-T5~T7)는 부품을 렌더하지 않고 HTML 조각에 검사 함수를 돌리므로 L1이다. jsdom이 필요해서 파일이 `// @vitest-environment jsdom`을 단다.

## 찾은 것

- **상자 검사에 테스트가 없다.** `visual/checks.ts`의 `runBoxChecks`(옆으로 스크롤되는 쪽, 상자에 잘린 글자, 계산된 크기가 맞지 않는 글자 역할)를 보는
  단위 테스트가 없다. 테스트를 더할 때 UI-T8로 줄을 단다.
- **시각 검사기의 테스트는 브라우저 API를 스텁한다.** `visual-checks.test.ts`는 `getBoundingClientRect`, `Range.getClientRects`, 캔버스의 `measureText`를
  지어낸다. 판단을 잰 값(상자, 줄, 글꼴 수치)을 받는 함수로 뽑아 L1에서 보고, 브라우저에는 검사기가 실제 쪽에서 값을 읽는지 보는 테스트를 검사마다
  하나 두면 스텁이 사라진다. 코드 변경이라 따로 묶는다.
- **도구로 옮길 테스트 둘.** UI-T2(`tokens.test.ts`)는 `pnpm gen:tokens --check`로, UI-T4(`visual-setup.test.ts`)는 태그를 스토리에 글자 그대로 쓰게
  하는 lint 규칙으로 옮긴 뒤 지운다(#378). 그전에는 그 규칙을 아무것도 지키지 않아 ID를 단 채 둔다.
- **할 일 목록의 카드는 이름이 없는 대화 상자다.** 열리면 포커스를 받는 카드(`StatusBarList`)는 `dialog` 역할이지만 목록의 이름(`label`)으로
  이름 붙지 않는다. UI-K9의 테스트는 역할로만 찾는다.
