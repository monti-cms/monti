# 요구사항: 관리자 API

상태: 초안 (2026-10-31).

중요도: [기능의 중요도](../features.md)의 "HTTP API"(제안대로, 2026-10-31). 관리자만 부르기, 같은 출처 검사, cron과 다시 보내기의 토큰,
본문 크기 한도, 라우트마다 정한 접근은 🔴이다. 라우터와 작업(operations)은 🟡라서 대표 약속만 적는다. 오류 응답의 문장은
[관리자의 바탕](admin.md)의 ADMIN-E1·E2, 공개 JSON API는 [사이트](site.md)의 SITE-R5·J1, 플러그인 라우트는 [관리자 플러그인](plugins.md)의
PLUG-S1이 다룬다. `admin.templates: false`가 템플릿 API를 닫는 것은 화면을 숨기는 것과 같은 옵션이라 ⚪다. 흐름이 따로 없다.
읽는 법은 [휴지통](trash.md#읽는-법)과 같다.

## 지키기 🔴

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| API-G1 | 관리자 API의 라우트는 모두 관리자만 부른다. 로그인 없이 부를 수 있는 것은 정한 것뿐이다(로그인·로그아웃·첫 관리자 폼, 공개 JSON API, 서명을 스스로 보는 웹훅, 비밀값을 든 cron). 플러그인 라우트도 따로 정하지 않으면 관리자 전용이고, 공개 읽기 라우트는 읽기 말고는 405다. 로그인하지 않으면 401, 로그인했지만 관리자가 아니면 403이다 | 누구나 글을 바꾸거나 지운다 | 코드 · 소유자 확인 (2026-10-31) | L1 |
| API-G2 | 상태를 바꾸는 요청은 같은 출처에서 온 것만 받고, 출처 검사는 로그인 검사보다 먼저다. 출처를 알 수 없으면 거부한다. `X-Forwarded-Host`는 믿는 프록시일 때만 첫 값을 보고, 사이트 주소(`site.url`)의 호스트도 받는다. 로그인 없는 폼 라우트에도 검사가 붙고, 읽기는 검사하지 않는다 | 다른 사이트의 페이지가 관리자의 브라우저로 글을 지운다 | 코드 · 소유자 확인 (2026-10-31) | L1 |
| API-G3 | cron 라우트(이벤트 다시 보내기, 휴지통 저절로 지우기)는 관리자 세션이나, 서버 설정의 비밀값과 정확히 같은 Bearer 토큰을 받는다. 틀린 토큰과, 비밀값을 설정하지 않은 사이트의 어떤 토큰도 401이다. 토큰이 없으면 관리자 라우트처럼 지킨다 | 누구나 다시 보내기와 영구 삭제를 돌린다 | 코드 · 소유자 확인 (2026-10-31) | L1 |
| API-G4 | 요청 본문은 읽기 전에 크기를 본다. 밝힌 크기가 한도를 넘으면 읽지 않고, 크기를 밝히지 않은 본문은 세며 읽다가 넘는 순간 끊는다(413). 로그인 전의 폼은 더 작은 한도다 | 큰 요청 하나가 서버의 메모리를 다 쓴다 | 코드 · 소유자 확인 (2026-10-31) | L1 |

## 길 🟡

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| API-R1 | `cms.handle`은 요청 주소에서 경로를 읽는다(디코드하고, 쿼리와 빈 칸은 버린다). 호스트가 나눠 준 경로도 받는다. 이름이 정해진 칸(`search`, `counts`)이 `[id]`보다 먼저 맞고, 모르는 경로는 404, 그 경로에 없는 메서드는 405다 | 배포한 뒤 관리자 API가 404가 되거나, `search`를 글 id로 읽는다 | 코드 | L1 |

## 작업 🟡

core의 읽기 API를 이름으로 부르는 작업이다. 관리자 라우트 몇 개(meta, 목록, 찾기, 하나 읽기, 템플릿)와 어시스턴트의 도구가 이것을 부른다.
변경의 작업자(actor)는 ⚪다.

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| API-O1 | 인스턴스의 작업은 core의 작업과 플러그인의 작업(플러그인 이름이 붙는다)이다. 작업마다 점으로 나눈 이름, 모델에게 줄 설명, JSON Schema로 바뀌는 입력이 있고, 입력은 이 사이트의 컬렉션 이름을 안다. 이름이 틀리거나 설명이 없거나 이름이 겹치면 양쪽을 대며 정의할 때 실패한다 | 어시스턴트가 시작하지 못하거나 다른 사이트의 컬렉션 이름을 받는다 | 코드 | L1 |
| API-O2 | 작업은 스키마로 읽은 입력(쿼리 글자는 숫자로, 빠진 값은 기본값으로), 인스턴스, 취소 신호를 받는다. 맞지 않는 입력은 문제와 함께 거부하고 돌지 않으며, 없는 이름은 `not_found`다 | 어시스턴트가 잘못된 입력으로 작업을 돌리거나, 멈춘 요청이 계속 돈다 | 코드 | L1 |

## 찾은 것

### 약속 없는 테스트 나누기 (2026-10-31)

- **라우트 표의 접근을 보는 테스트가 없다.** 라우트 테스트의 도우미(`routeCaller`, `callRoute`)는 접근을 라우터 표(`ROUTES`)에서 읽지 않고
  부르는 쪽에서 받는다. 그래서 라우트마다 있는 401·403 테스트는 표에 잘못 적힌 `access: "public-read"`를 잡지 못한다. API-G1에
  `CMS_ROUTE_PATTERNS`를 돌며 정한 예외 밖은 모두 `admin`인지 보는 L1 테스트 하나를 더한다. 그러면 라우트마다의 가드 테스트(겹침)를 지워도
  잃는 것이 없다.
- **출처 검사의 빈틈**(API-G2): `Sec-Fetch-Site`가 cross-site인 요청, `Referer`만 있는 요청, JSON 라우트에 `text/plain`으로 보낸 요청(415)을
  보는 테스트가 없다.
- 본문이 문서인지 글인지 가르는 `bodyIsDocOrText`와 문서 한도·문서가 아닌 값을 거르는 `documentInputBody`에 L1 테스트가 없다(WRITE-S7).
  라우트에서 그 경우를 보는 테스트 6개(아래로)는 L1 테스트를 더한 뒤에 지운다.
- 발행 라우트가 `resetPublishedAt`을 서비스에 넘기는지 보는 테스트가 없다(WRITE-P5).
