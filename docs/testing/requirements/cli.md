# 요구사항: 명령줄

상태: 초안 (2026-10-31).

중요도: [기능의 중요도](../features.md)의 "흐름에 없는 core의 기능"(제안대로, 2026-10-31). `monti init`이 사람의 파일과 비밀을 지키는 것과
처음 사이트가 뜨는 것, 비밀값을 찍지 않는 것은 🔴이다. init의 설치·묻기·앱 읽기·남은 일과 `monti doctor`, 그 밖의 명령줄은 🟡라서 대표
약속만 적는다. 도움말과 질문의 문구, 힌트, hydration 경고는 ⚪다. 흐름이 따로 없다. 데이터베이스 명령(`db:setup`, `db:migrate`)은
[데이터베이스](database.md), 스키마 명령은 [컬렉션과 스키마 적용](collections.md), `admin:reset-password`는 [처음 설치와 로그인](first-install.md)의
AUTH-L12, 플러그인 명령은 [관리자 플러그인](plugins.md)의 PLUG-S2가 다룬다. 읽는 법은 [휴지통](trash.md#읽는-법)과 같다.

## init: 사람의 파일과 비밀 지키기 🔴

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|

| INIT-K2 | `.env.local`은 다시 쓰지 않는다. 비었거나 없는 `MONTI_SECRET`만 채우고(없으면 끝에 더한다), 다른 줄은 글자 그대로 둔다. 이미 있는 비밀은 바꾸지 않는다. 채우는 값은 Monti가 그 자리에서 만드는 무작위 값이고, 데이터베이스 주소나 다른 계정의 값은 채우지 않는다 | 데이터베이스 주소가 사라지거나, 비밀이 바뀌어 모두 로그아웃되고 저장한 AI 키를 읽지 못한다 | 코드 · 소유자 확인 (2026-10-31) | L2 |
| INIT-K3 | 앱의 파일은 `next.config`, 루트 레이아웃, `.gitignore`만 고치고, 고친 파일마다 무엇을 바꿨는지 알린다. 두 번 돌려도 같다. 고치지 못한 것은 이유와 고칠 내용을 남은 일에 적는다 | init이 앱의 다른 파일을 바꾸거나, 두 번째 실행이 `withCms(withCms(…))`를 만든다 | 코드 · 소유자 확인 (2026-10-31) | L2 |
| INIT-K4 | 파일을 고칠지는 그 모양으로 정한다. `next.config`는 식별자, 객체, 호출인 export만 감싸고(이미 Monti의 `withCms`를 부르면 그대로 두고, 주석이나 글자 속의 이름은 세지 않는다), 함수, `satisfies`, CommonJS는 손대지 않는다. `<html>`은 끝까지 읽을 수 있을 때만 `suppressHydrationWarning`을 더한다 | init이 `next.config`나 레이아웃을 깨서 사이트가 빌드되지 않는다 | 코드 · 소유자 확인 (2026-10-31) | L1 |
| INIT-K5 | 비밀은 git 밖에 둔다. `.gitignore`가 `.env.local`과 `.monti/`를 덮게 하고(이미 덮는 줄은 철자가 달라도 그대로 둔다), git에 올라가는 `.env.example`에는 비밀값을 쓰지 않는다 | 비밀과 데이터베이스 주소가 저장소에 올라간다 | 코드 · 소유자 확인 (2026-10-31) | L1 |
| INIT-K6 | 프로젝트 폴더 안에만 쓴다. 절대 경로, `..`, 밖으로 가는 심볼릭 링크(폴더 포함)는 쓰기 전에 거부한다 | init이 프로젝트 밖의 파일을 덮는다 | 코드 · 소유자 확인 (2026-10-31) | L2 |
| INIT-K7 | 쓰기 전에 끝나는 것(잘못된 플래그, 취소, Next App Router 앱이 아님, dry run)은 아무것도 쓰지 않는다. 쓰다가 실패하면 그때까지 쓴 파일을 대고 다시 돌리라고 한다. 취소는 130으로 끝난다 | 반쯤 쓴 프로젝트에서 무엇이 바뀌었는지 모른다 | 코드 · 소유자 확인 (2026-10-31) | L2 |
| INIT-K8 | 새로 만드는 `MONTI_SECRET`은 32바이트 무작위 값이고 매번 다르다 | 사이트마다 같은 비밀이나 약한 비밀이 되어 세션을 위조할 수 있다 | 코드 · 소유자 확인 (2026-10-31) | L2 |

## init: 설치, 묻기, 남은 일 🟡

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| INIT-I1 | 설치는 앱의 패키지 관리자(lockfile, `packageManager` 필드, `--package-manager`)로, core와 같은 출처에서 한다(GitHub 주소면 같은 ref의 그 패키지 폴더, 버전 범위면 이름만). 사람에게 맡긴 명령은 셸에 붙여 넣어도 같은 인자다 | 버전이 다른 Monti 패키지가 섞이거나, 다른 패키지 관리자로 설치된다 | 코드 | L2 |
| INIT-Q1 | 질문마다 플래그가 있고, 플래그가 정한 것은 묻지 않는다. 터미널이 없거나 `--yes`, `--json`이면 아무것도 묻지 않고 기본값을 쓴다. "추천 설정"은 기본 언어와 로그인만 묻고 나머지는 기본값이다. 받은 답은 그대로 설정이 된다 | CI에서 init이 질문을 기다리며 멈추거나, 추천을 고른 사람이 모르는 설정을 받는다 | 코드 | L2 |
| INIT-Q2 | 로그인은 정하지 않고 넘어가지 않는다. 터미널에서는 `--login`이 없으면 늘 묻고(이메일과 비밀번호가 먼저, GitHub가 다음, "로그인 없음"은 없다), 터미널이 없을 때만 이메일과 비밀번호가 기본이다. `--login`은 `password`와 `github`만 받는다 | 모르는 사이에 GitHub 로그인이 되어 OAuth 앱 없이는 관리자에 들어가지 못한다 | 소유자 결정(로그인 설계) | L2 |
| INIT-Q3 | 콘텐츠의 파일 이름(`hello.ko.mdx`)이나 언어 폴더(`content/ko`)에서 언어를 찾고, 짝이 없는 쪽을 기본 언어로 한다. 낱말(`release.notes.md`, 폴더 하나)은 언어로 보지 않는다. `--locales`가 이기고, 겹친 언어는 하나로, 목록에 없는 언어는 코드로 친다 | 가져올 글의 언어가 틀리게 잡혀 번역이 원문으로 들어온다 | 코드 | L1 |
| INIT-Q4 | 시간대는 이 컴퓨터를 따르고 묻지 않으며, `--time-zone`이 이긴다. 읽지 못하면 UTC로 하고 그렇다고 알리며, 어느 파일의 무엇을 바꾸면 되는지 말한다 | 예약 발행이 엉뚱한 시각에 된다 | 코드 | L1 |
| INIT-C1 | 콘텐츠 폴더의 front matter에서 글 컬렉션의 필드를 만들고(맨 위 키만, 종류를 맞춰), 콘텐츠 파일은 건드리지 않는다 | 가져올 글의 값이 들어갈 필드가 없다 | 코드 | L2 |
| INIT-S1 | 설치, `.env.local`, 데이터베이스, 점검은 한 번 묻고(기본 "예") 차례로 돈다. 하나가 실패해도 나머지를 돌리고, 결과는 실패로, 종료 코드는 1로 남기며 쓴 파일은 그대로다. 패키지가 없으면 데이터베이스와 점검은 기다리고, 진짜 데이터베이스 주소가 없으면 데이터베이스를 건너뛴다 | 설치 실패 하나에 init이 반쯤 멈추거나, 실패를 성공으로 알린다 | 코드 | L2 |
| INIT-N1 | 끝나면 요약과, 기계가 하지 못한 일만 정확한 명령과 함께 차례로 적은 남은 일을 보인다(앱의 패키지 관리자, dev 포트, 관리자 주소, 로그인에 맞게). 건너뛰거나 실패한 단계는 그 명령과 함께 남는다. 배포한 직후 첫 관리자를 만들라고 알린다 | 처음 설치한 사람이 무엇을 해야 할지 모르거나, GitHub 콜백 주소가 다른 포트를 가리킨다 | 코드 | L2 |
