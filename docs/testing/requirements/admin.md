# 요구사항: 관리자의 바탕

상태: 초안 (2026-10-31).

중요도: [기능의 중요도](../features.md)의 "관리자 전체" 🟡(제안대로, 2026-10-31). 관리자를 사이트 안에서 돌리기(CSS 격리, 테마 덮기,
서버에서 불러도 깨지지 않기), 오류 알림, 관리자 주소, 컬렉션 이름을 쓰는 문구, 기기마다 기억하는 값이 막힌 저장소와 잘못된 값에 깨지지 않는 것이다.
템플릿 화면은 [템플릿](templates.md)에 있다. 관리자 틀(사이드바의 순서, 접기, 좁은 화면의 서랍), 화면 모드 전환, 그 밖의 기억하는 값은 ⚪라
줄이 없다. 흐름이 따로 없다. 읽는 법은 [휴지통](trash.md#읽는-법)과 같다.

## 사이트 안에서 돌리기 🟡

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| ADMIN-H1 | 관리자와 블록의 배포 CSS는 관리자를 담은 문서에서만 걸린다(초기화도 그 안에서만). 사이트의 이름(사용자 정의 속성, `--tw-*`, 키프레임, 레이어)을 정의하거나 읽지 않고, 묶음끼리 같은 선택자를 두 번 정의하지 않는다. 토큰과 `color-scheme`, KaTeX는 배포 CSS에 들어 있다 | 관리자 CSS를 불러온 사이트의 공개 페이지 모양이 바뀐다 | 코드 · 제안대로 (2026-10-31) | L1 |
| ADMIN-H2 | 관리자와 first-party 플러그인이 쓰는 모든 유틸리티가 배포 CSS에 들어 있다 | 플러그인 화면 일부가 스타일 없이 나온다 | 코드 · 제안대로 (2026-10-31) | L1 |
| ADMIN-H3 | 관리자의 화면 모드는 자기 키에 저장하고 사이트의 테마 키를 건드리지 않는다. 관리자를 떠나면 사이트의 `html` 클래스와 `color-scheme`을 관리자가 오기 전으로 되돌린다(새로 고친 페이지에서도) | 관리자에서 어둡게 하면 사이트도 어두워지거나, 사이트의 어두운 테마가 풀린다 | 코드 · 제안대로 (2026-10-31) | L3 |
| ADMIN-H4 | `@monti-cms/admin` 루트는 서버 컴포넌트에서 불러도(`react-server` 조건) 깨지지 않는다. `"use client"` 모듈은 가리키기만 하고, 서버가 읽는 모듈은 읽을 때 `createContext`나 클라이언트 훅을 부르지 않는다 | 플러그인의 관리자 모듈이 `defineAdminPlugin`을 가져오는 순간 관리자 모든 화면이 서버에서 깨진다 | 코드 | L1 |

테스트를 고쳐 쓴 뒤에 줄이 될 약속이 하나 있다.

- 사이트가 `--monti-*` 토큰을 덮으면 불러오는 순서와 상관없이 그 값이 이기고, 단계 색을 덮으면 그것을 가리키는 역할이 두 모드 모두 따라 바뀐다.
  앞 절반(토큰 블록의 특정도가 0)은 `css-confinement.test.ts`가 빌드 결과에서 본다. 뒤 절반(역할은 한 번만 선언하고 단계를 가리킨다)은
  테스트 대신 `pnpm gen:tokens`가 지킨다. 어기는 토큰이면 아무것도 쓰지 않는다(#378).

ADMIN-H4는 루트를 실제로 불러 본다(`entry-loading.test.ts`). 같은 파일이 편집기 훅(`hooks/public.ts`)도 불러 보고, 훅이 관리자의 기본 UI와 라우터,
호스트 틀을 불러오지 않고 프레임워크와 아이콘 패키지를 가져오지 않으며 주소를 바꾸지 않는지 본다. 맞는 줄이 없어 ID 없이 둔다.

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| ADMIN-U1 | 관리자 주소가 화면을 고른다. 휴지통과 미디어, 설정의 탭, 도구의 탭(플러그인 페이지 포함), 새 템플릿과 템플릿 편집이 저마다 주소를 갖고, 관리자 경로나 `basePath` 아래에서도 탭을 읽는다. 설정과 도구의 맨 주소는 첫 탭으로 가고, 탭을 바꿔도 쿼리는 남는다. 모르는 탭, 옛 탭 주소, 더 깊은 경로는 404다 | 북마크한 주소가 404가 되거나 다른 화면을 열고, 탭을 바꾸면 열어 둔 컬렉션을 잃는다 | 코드 · 제안대로 (2026-10-31) | L1 |

| ID | 약속 | 틀리면 | 출처 | 층 |
|---|---|---|---|---|
| ADMIN-E1 | 서버가 거부하면 서버의 문장과 고치는 법을 보인다. 문제가 여럿이면 제목 아래 한 줄씩, 자리와 함께 보이고, 그때 고치는 법 한 줄은 붙이지 않는다. 화면이 쓴 문장(`NoticeError`)은 그대로 보인다 | 무엇을 고쳐야 할지 모른다 | 코드 · 제안대로 (2026-10-31) | L1 |
| ADMIN-E2 | 예상하지 못한 오류의 문장(브라우저와 코드의 영어)은 보이지 않고 화면의 대체 문장과 "자세히"에만 남는다. 서버에 닿지 못하면 오프라인이라고 알린다 | `Unexpected token < in JSON`이 관리자에게 보이거나, 연결 끊김을 서버 오류로 안다 | 코드 · 제안대로 (2026-10-31) | L1 |
| ADMIN-E3 | core가 거부할 때 쓰는 알림 사전은 관리자 언어마다 같은 키를 갖고, 같은 키는 두 언어에서 같은 값을 채우며 채우지 않은 자리표를 남기지 않는다 | 한국어 관리자에게 영어 문장이 나오거나, `{fields}`가 그대로 보여 어느 필드인지 모른다 | 코드 | L1 |
