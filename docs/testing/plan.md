# 테스트 줄이기 계획

정비의 목표는 결함을 잡으면서 돌리고 고치는 비용이 적은 테스트다. 지금까지는 망가진 테스트를 고치고 구조를 정리했다(core 1·2단계).
이제부터는 [기능의 중요도](features.md)를 기준으로 테스트를 줄인다. 소유자와 정했다(2026-10-30).

## 하는 법

1. 기능 하나(흐름의 세부 흐름 몇 개)를 고르고, 그 기능을 검사하는 테스트를 모은다.
2. 중요도에 맞게 남길 것을 정한다. 🔴은 대표 테스트를 남기고 겹치는 것만 뺀다. 🟡은 흐름 하나와 핵심 판단 몇 개만 남긴다. ⚪은 거의 다 지운다.
3. 판단이 화면 안에 묻혀 경우마다 화면을 띄워 검사하고 있으면, 판단을 함수로 뽑아 L1에서 한 번만 검사하고 화면 테스트를 지운다.
4. 지우기 전과 뒤의 커버리지를 견준다. 🔴 기능의 코드가 더는 실행되지 않으면 그것만 다시 본다.
5. 테스트를 더해야 하면 PR 전에 이유를 한 줄로 말하고 허락을 받는다.

## 순서

1. admin의 🟡·⚪ 기능부터 한다. 시간의 62%가 admin에 있다. 첫 PR은 흐름 7 목록 정리의 정렬, 열과 쪽, 거르기다.
2. core에서 같은 동작을 여러 층에서 겹쳐 검사하는 것과, 다른 사이트 설정으로 다시 돌 필요가 없는 테스트를 덜어낸다.
3. 🔴 기능을 신중하게 정리한다.
4. 나머지 패키지.

## 보고

PR마다 테스트 수, 실행 시간, 🔴 기능 커버리지의 전후와 걸린 작업 시간을 적는다. PR 하나가 끝나면 멈추고 소유자의 확인을 받은 뒤 다음으로 간다.
