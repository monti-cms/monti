# 흐름 테스트가 지키는 이음매

상태: 끊어 보기를 마쳤다 (2026-11-01).

L4 흐름 테스트(`flows/*.flow.ts`)는 아래 층이 볼 수 없는 것, 곧 **조각을 다 합쳐야만 깨지는 곳**을 지킨다. 경우는 아래 층이 본다.
흐름이 있는지는 [기능의 중요도](features.md)의 🔴 흐름마다 하나라 이미 맞다. 이 문서가 묻는 것은 그다음이다. 각 흐름은 어느 이음매를
지키나, 그 이음매를 끊으면 흐름이 실패하나.

흐름은 묶은 패키지로 설치한 예제 앱(`flows/.app`)을 `next dev`로 띄우고 진짜 데이터베이스에서 돈다. 프로덕션 빌드(`next build`, 두 가지
`cacheComponents`)는 흐름이 아니라 CI의 예제 검사(`pnpm example:check`)가 본다.

## 흐름마다

"끊은 것"은 그 흐름 하나만 돌리며 실제로 망가뜨린 곳이다. 예제와 `flows/overlay`의 파일은 소스에서, 패키지 코드는 `flows/.app`에 설치된
`dist`에서 고쳤다가 되돌렸다.

| 흐름 | 지키는 이음매 | 끊은 것 | 결과 |
|---|---|---|---|
| 1 글 쓰고 발행 (`write-and-publish`) | 관리자 화면 → 발행 라우트 → 데이터베이스 → 블로그 페이지가 본문을 그린다. 고쳐 다시 발행하면 블로그가 새 본문을 그린다 | 글 페이지가 본문을 그리지 않게 함 · 다시 발행이 발행본을 쓰지 않게 함 | 둘 다 실패. 처음에는 본문을 지워도 **통과했다**(아래) |
| 3 번역 (`translate`) | 번역 발행 → 블로그의 언어 경로(`/en/…`)가 원문이 아니라 번역을 그린다 | 글 페이지가 주소의 언어를 무시하게 함 | 실패. 본문 확인을 글의 `article`로 옮겼다(아래) |
| 4 컬렉션 (`collections`) | 설정 화면 → 스키마 파일을 디스크에 쓴다 → 데이터베이스 적용 → 다시 읽은 스키마로 글쓰기 화면이 바뀐다 | 스키마 저장이 `monti.schema.ts`를 쓰지 않게 함 | 실패 |
| 5 휴지통 (`trash`) | 발행한 글을 버리면 블로그에서 내려간다(404). 글의 버리기 → 휴지통 화면 → 복원과 영구 삭제, 비우기 | 복원 라우트를 라우트 표에서 뺌 · 블로그 읽기가 버린 글도 내주게 함 | 둘 다 실패 |
| 6 미디어 (`media`) | 업로드 → 저장소 → 고르기 창 → 글에 넣기 → 쓰이는 곳 표시. 발행하면 블로그가 저장소의 공개 주소로 그림을 불러온다 | 저장소가 올린 파일을 쓰지 않게 함 · 공개 주소가 없는 경로를 가리키게 함 | 둘 다 실패 |
| 7 목록 정리 (`list`) | 목록에서 여러 글 고르기 → 일괄 라우트 → 데이터베이스 → 다시 읽은 목록에 태그가 보인다 | 일괄 라우트가 태그를 쓰지 않게 함 | 실패. 처음에는 **통과했다**(아래) |
| 8 처음 설치 (`first-install`) | 비밀번호 로그인 앱(`flows/.app-login`)에서 첫 관리자 폼 → 세션 쿠키 → 다시 들어와 로그인 | 세션 읽기가 쿠키를 넘기지 않게 함 | 실패 |
| 9 데이터 (`data`) | 백업 zip 내려받기 → 사이트 비우기(블로그 404) → zip 올려 복원 → 블로그 200과 본문 | 복원이 발행본의 본문을 비워 쓰게 함 | 실패. 처음에는 **통과했다**(아래) |

## 찾은 것

- **흐름 셋이 이음매를 끊어도 통과했다.**
  - 흐름 1과 9는 본문을 페이지 HTML 전체에서 찾았다. 발행할 때 본문에서 만든 요약이 `<meta description>`에도 있어서, 본문을 그리지 않아도
    글자가 남는다. 이제 글의 `article` 안에서 찾는다. 흐름 3도 같은 식으로 고쳤다.
  - 흐름 7은 목록이 서버의 답을 기다리지 않고 먼저 보이는 태그를 확인했다. 이제 다시 불러온 목록에서 확인한다.
- **빈틈 셋을 흐름에 더했다.** 다시 발행(흐름 1), 발행한 글을 버리면 블로그에서 내려감(흐름 5, 🔴 "버린 글이 사이트에서 내려가기"), 블로그의
  그림(흐름 6). 셋 다 끊었을 때 실패하는 것을 확인했다.
- **흐름은 통과해도 서버가 오류를 남길 수 있다.** 비밀번호 로그인 앱의 `/studio`가 미리 그리는 동안 난수를 읽어 `next dev`가 매번 오류를 남겼고,
  로그인 뒤 관리자로 넘어갈 때 브라우저도 오류를 남겼다(관리자 테마의 `<script>`). 화면은 동작해서 흐름이 통과했다(#389). 둘 다 고쳤고,
  이제 `pnpm flows`가 흐름을 다 돌린 뒤 두 앱의 `next dev` 기록(`.next/dev/logs/next-development.log`)을 읽어 오류가 하나라도 있으면 실패한다.

## 다음에 끊어 볼 때

흐름을 바꾸면 그 흐름의 이음매를 위 표대로 다시 끊어 본다. 흐름 한 번에 1분쯤 걸린다.

```bash
pnpm flows --prepare     # 패키지를 묶어 flows/.app에 설치한다(코드를 바꾼 뒤 한 번)
pnpm flows -- trash.flow.ts
```
