# 흐름 테스트가 지키는 이음매

상태: 초안 (2026-11-01). 끊어 보는 확인은 아직 하지 않았다.

L4 흐름 테스트(`flows/*.flow.ts`)는 아래 층이 볼 수 없는 것, 곧 **조각을 다 합쳐야만 깨지는 곳**을 지킨다. 경우는 아래 층이 본다.
흐름이 있는지는 [기능의 중요도](features.md)의 🔴 흐름마다 하나라 이미 맞다. 이 문서가 묻는 것은 그다음이다. 각 흐름은 어느 이음매를
지키나, 그 이음매를 끊으면 흐름이 실패하나.

흐름은 묶은 패키지로 설치한 예제 앱(`flows/.app`)을 `next dev`로 띄우고 진짜 데이터베이스에서 돈다. 프로덕션 빌드(`next build`, 두 가지
`cacheComponents`)는 흐름이 아니라 CI의 예제 검사(`pnpm example:check`)가 본다.

## 흐름마다

| 흐름 | 지키는 이음매 | 끊어 볼 방법 | 빈틈 |
|---|---|---|---|
| 1 글 쓰고 발행 (`write-and-publish`) | 관리자 화면 → 발행 라우트 → 데이터베이스 → 블로그 페이지가 본문을 그린다 | 예제의 글 페이지가 `getEntry`의 본문을 그리지 않게 바꾼다 | 이미 발행한 글을 고쳐 다시 발행했을 때 블로그가 새 글을 보이는지(캐시)는 보지 않는다 |
| 3 번역 (`translate`) | 번역 발행 → 블로그의 언어 경로(`/en/…`)가 번역을, 원문 아닌 것을 그린다 | 예제 설정의 언어 접두어를 바꾸거나, 글 페이지가 언어를 무시하게 한다 | — |
| 4 컬렉션 (`collections`) | 설정 화면 → 스키마 파일을 디스크에 쓴다 → 데이터베이스 적용 → 다시 읽은 스키마로 글쓰기 화면이 바뀐다 | 스키마 라우트가 파일을 다른 경로에 쓰게 하거나, 다시 읽기를 끈다 | — |
| 5 휴지통 (`trash`) | 글의 버리기 → 휴지통 화면 → 복원과 영구 삭제, 비우기 | 휴지통 라우트 하나를 라우트 표에서 뺀다 | **발행한 글을 버리면 블로그에서 내려가는지 보지 않는다.** 이 흐름의 글은 발행한 적이 없다. 영구 삭제 뒤의 404는 흐름 9가 본다 |
| 6 미디어 (`media`) | 업로드 → 저장소(`flows-storage`) → 고르기 창 → 글에 넣기 → 쓰이는 곳 표시 | 저장소 어댑터가 파일을 쓰지 않게 한다 | **블로그가 그 그림을 공개 주소로 보이는지 보지 않는다**(저장소의 공개 주소 → 페이지의 `<img>`) |
| 7 목록 정리 (`list`) | 목록에서 여러 글 고르기 → 일괄 라우트 → 데이터베이스 → 목록과 편집기에 태그가 보인다 | 일괄 라우트가 태그를 쓰지 않게 한다 | — |
| 8 처음 설치 (`first-install`) | 비밀번호 로그인 앱(`flows/.app-login`)에서 첫 관리자 폼 → 세션 쿠키 → 다시 들어와 로그인 | 세션 쿠키 이름이나 서명 비밀을 바꾼다 | — |
| 9 데이터 (`data`) | 백업 zip 내려받기 → 사이트 비우기(블로그 404) → zip 올려 복원 → 블로그 200과 본문 | 백업에서 글 하나를 빼거나, 복원이 본문을 쓰지 않게 한다 | — |

## 할 일

- **끊어 보기**: 위 "끊어 볼 방법"대로 하나씩 끊고 그 흐름이 실패하는지 본다. 실패하지 않으면 그 흐름은 이름만 흐름이므로 고친다.
  흐름 한 번에 몇 분이 걸려서, 변이 테스트가 돌지 않을 때 한다.
- **빈틈 셋**: 발행한 글을 고쳐 다시 발행(흐름 1), 발행한 글을 버리면 블로그에서 내려감(흐름 5, 🔴 "버린 글이 사이트에서 내려가기"),
  블로그의 그림(흐름 6)은 Next의 캐시와 저장소의 공개 주소가 걸린 이음매라 아래 층이 볼 수 없다. 각 흐름에 확인 한 줄씩을 더한다.
- ID가 없는 흐름 둘(미디어, 글 쓰고 발행)과 하나의 ID만 단 흐름에, 이 표의 흐름 번호를 제목에 남긴다. 개수를 세는 검사는 만들지 않는다.
