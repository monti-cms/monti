# 미디어 라이브러리 사용성 시험 2

- 대상: 기능 문서 09, 시험 서버 `http://localhost:4173`, 2026-11-09.
- 방법: 지정된 `node testing/usability/do.ts` 드라이버의 마우스·키보드·파일 입력과 화면 캡처. 서버는 시작하거나 중지하지 않았다. 아래 좌표는 별도 언급이 없으면 1440×900 기준이다. 그림 경로는 이 저장소 기준이다.
- 시험 데이터: 로그인 후 제공된 파일을 올렸다. 200개 PDF를 두 번 올려 보았고, 글 두 개와 폴더 및 미디어를 시험 과정에서 변경했다. 실제 사용자 데이터가 아닌 방금 심어진 시험 데이터다.
- 판정: 성공하지 못한 모든 항목을 결함으로 세지 않았다. 조작하지 않았거나 결과를 확인할 수 없었던 부분은 아래 완료 표에 따로 적었다.

## 결함

### B-1. 자르기·회전 적용 직후 ⌘Z가 동작하지 않는다

- **시나리오:** U5.
- **입력 기록:** `아침의 책상` 편집기에서 PNG를 붙여 넣고 이미지를 선택 → `자르기와 회전` → `자를 곳 잡기` → 오른쪽 아래 모서리를 `(1361,393)`에서 `(1250,330)`으로 드래그 → `오른쪽으로 돌리기` → `적용` → 다른 곳을 누르지 않고 `key Meta+Z`. 이어서 이미지 `(400,500)`를 누르고 `key Meta+Z`를 다시 눌렀다.
- **그림:** 자르기 [048](feat-media-09-2/048-u5-crop-drag.png), 회전 적용 직후 [050](feat-media-09-2/050-u5-rotated.png), 첫 ⌘Z 뒤 [051](feat-media-09-2/051-u5-undo.png), 이미지를 다시 누르고 ⌘Z를 누른 뒤 [052](feat-media-09-2/052-u5-undo-focused.png).
- **기대와 근거:** 그림을 편집한 직후 편집 동작을 되돌릴 수 있어야 한다. 기능 09의 글 속 이미지와 관리자 `screens/editor.md`의 이미지 도구는 자르기·회전을 편집기에서 적용하는 동작으로 설명한다. 시험 목표는 회전 직후 ⌘Z로 되돌리는 것이다.
- **실제:** 적용 직후 ⌘Z에서는 회전된 세로 그림이 그대로였다. 그림을 다시 클릭한 뒤 ⌘Z를 누르자 가로 그림으로 돌아갔다. 추가 클릭이 필요하다는 사실은 화면에서 알기 어려웠다. 자르기와 회전을 한 번에 적용했으므로 두 변화가 각각 별도 실행 취소 단계인지까지는 판정하지 않았다.

### B-2. 번역이 원문의 어느 시점의 대표 이미지를 따르는지 알기 어렵다

- **시나리오:** U11.
- **입력 기록:** `아침의 책상`에서 `표지-봄.jpg`와 대체 텍스트 `봄표지`를 지정해 발행 → `+ 언어`에서 English 생성 → 대표 이미지가 원문 것을 따르는 상태 확인 → 한국어로 돌아가 대표 이미지를 `서울의-밤.jpg`로 바꾸고 **저장만** 함 → English의 속성 패널을 연다.
- **그림:** 발행한 원문 [028](feat-media-09-2/028-u11-publish.png), 번역의 최초 속성 [032](feat-media-09-2/032-u11-properties.png), 원문 저장 후 번역 [039](feat-media-09-2/039-u11-published-source.png).
- **기대와 근거:** 기능 04 **원칙 5**에 따라 번역은 원문의 발행본을 따른다. 기능 09의 글 속 이미지 및 `screens/editor.md`의 번역 대표 이미지 규칙은 빈 번역 값이 원문을 따른다고 정한다. 따라서 저장만 한 새 이미지가 번역에 반영되지 않는 동작 자체는 맞다. 다만 사용자가 보고 있는 값의 출처와 원문의 최신 편집값이 보이지 않는 이유를 화면에서 이해할 수 있어야 한다.
- **실제:** 번역에는 이전 `표지-봄.jpg`와 `봄표지`가 보였다. 화면에는 이 값이 **원문의 발행본**에서 왔다는 설명이나 원문에 미발행 변경이 있다는 표시가 없어, 원문에서 방금 저장한 `서울의-밤.jpg`가 보이지 않는 이유를 이 화면만으로 알 수 없었다. 원문 따름과 번역 자체 값도 흐린 표시와 ×의 유무로만 구분해야 했다.

### C-1. 긴 파일 이름이 목록과 패널에서 잘려 전체를 훑어보기 어렵다

- **시나리오:** U10.
- **입력 기록:** `resize 1024 768` → 긴 한글 이름 TXT를 `dropfile` → 목록 보기 → 해당 행 클릭해 패널 열기. 별도로 이름 일부로 검색해 격자도 확인했다.
- **그림:** 목록 [018](feat-media-09-2/018-u10-long-list2.png), 패널 [019](feat-media-09-2/019-u10-long-panel.png), 격자 [100](feat-media-09-2/100-u10-long-grid1024.png).
- **기대와 근거:** `screens/media.md`의 목록은 이름과 사용 여부·종류·크기 등을, 패널은 파일 이름과 정보를 보여 주도록 한다. 긴 이름도 파일을 식별할 수 있게 읽히는 편이 좋다.
- **실제:** 격자는 말줄임표가 보인다. 목록에서는 이름이 오른쪽 화면 경계에서 잘리고 나머지 정보 열도 처음 보이는 영역 밖으로 밀렸다. 패널 제목은 말줄임되고 이름 입력칸에도 앞부분만 보였다. 입력칸 안에서 커서를 옮겨 나머지를 읽을 수 있는지, 목록의 가로 스크롤로 나머지 열을 볼 수 있는지는 시험하지 않았다. 데이터 손실로 판정하지 않는다.
