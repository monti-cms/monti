Monti is being rebuilt from the feature docs in `docs/design/features` (order and rules in its `build.md`). Before any work, read `docs/tracker.md`: take the open items ("남은 일") of the doc you build into the PR, and write down any work you put off there, with the doc it is to be done with or the stage it is to be done before ("4단계 전"), never only in a PR description. There is no "before the release": an item without a time is picked up by nobody. `pnpm check:operations` refuses to mark a doc done while it has open items, or while items to be done before its stage are open.

Docs under `docs/` are written in Korean: the owner reads and approves them. Code names, file paths, tokens and commands in them stay as they are in the code. Everything else is in English (code comments, test titles, READMEs, error messages, commits, PRs); Korean appears elsewhere only in the `ko` message dictionaries, test data, Storybook stories and `README.ko.md`. When a `README.md` changes, update its `README.ko.md` in the same change.

Commit messages and PR titles follow Conventional Commits (`type(scope): subject`). The scopes are in `commitlint.config.mjs`; a new package adds its own.

Admin UI follows the rules in `docs/design/admin` (start at its README); change them in the same PR when a rule changes. Load the `admin-ui` skill first; `pnpm check:design` enforces its mechanical rules, and the `design-review` agent reviews each pull request before it joins a shared branch, by reading the code against the docs. It reads the whole pull request once, last (after the code review and the owner's look, 2026-11-11); what is fixed after that it reads as a delta: only the lines changed since, only for what a person would meet. The agent records what it read; `pnpm check:review` fails a commit whose admin UI is not the one on record, and a hook refuses `gh pr merge` of such a pull request, so nothing is merged unread. A small fix gets one code review; a feature doc's pull request gets two. Merge with `gh pr merge <number> --squash --match-head-commit <sha>`: the hook binds the merge to the head it checked. The `screen-check` agent tries the changed screens in a browser once on a pull request, last, after the owner has looked at them.

Prefer LSP for symbol navigation, references, types, rename and diagnostics.
